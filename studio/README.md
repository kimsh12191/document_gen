# docgen studio

은행 벤치마크 데이터 생성·관리 웹 도구. 생성기(`docgen`)의 서식·라벨을 보고 고치고, OCR·은행 업무 벤치마크를 만들며 데이터셋·모델 답·점수를 한 화면에서 관리한다. 합성 데이터, 이미지·PDF OCR 가져오기, **생성기 공통 형식의 라벨 폴더 검사·문항 생성·자동 등록**을 지원한다. 임의 모델 결과 형식의 가져오기와 항목 라벨 편집기는 아직 미구현이다. 설계는 [DESIGN.md](DESIGN.md), 내 데이터 준비와 UI 순서는 [DATA_IMPORT.md](DATA_IMPORT.md), 정답 규격은 [LABEL_FORMAT.md](LABEL_FORMAT.md), 기존 모델 결과 보조 경로는 [RESULTS_FORMAT.md](RESULTS_FORMAT.md), 학습 연결은 [TRAINING.md](TRAINING.md).

## 띄우기

저장소 루트에서:

```bash
pip install -r requirements.txt -r studio/requirements.txt
python -m studio                      # → http://localhost:8765
python -m studio --host 0.0.0.0       # 서버에서 띄우고 다른 PC 브라우저로 접속할 때
```

- **렌더링 브라우저:** Playwright 의 Chromium 이 없으면 설정의 `browser` → 환경변수 `CHROMIUM_PATH` → 이 PC의 Chrome·Edge 순으로 찾는다. 회사망에서 `playwright install chromium` 이 인증서 오류로 막혀도 설치된 Chrome 으로 돈다.
- **설정:** `studio/config.json` (git 제외). 바꿀 항목만 적는다. 예시는 [config.example.json](config.example.json).
- **내부망:** docgen 도커 컨테이너(Chromium·글꼴 포함)에서 띄우고, 윈도우 PC에서 SSH 터널로 접속한다. 이미지는 새로 반입하지 않는다. studio 패키지는 코드에 든 Linux 설치 파일(`studio/wheels/`)로 컨테이너 안에서 `python -m studio.deps install` 한 번이면 된다. 순서는 [docs/DOCKER.md 4절](../docs/DOCKER.md#4-studio-띄우기-같은-컨테이너).
  - 설치 파일 새로 받기(인터넷 되는 PC, 패키지 판을 바꿀 때만): `python -m studio.deps download`
  - 학습은 별도 학습 컨테이너에서 한다. 두 컨테이너는 폴더를 공유하고, 경로가 다르면 설정의 `path_map`으로 맞춘다([TRAINING.md](TRAINING.md)).
- **브라우저가 없을 때:** studio는 그대로 뜨고 렌더링(미리보기·합성 데이터 만들기)만 꺼진다. 등록부·평가·검수처럼 렌더링이 필요 없는 화면은 쓸 수 있다.
- 이 PC에서 만든 이미지는 글꼴이 서버와 다를 수 있다(나눔·Noto 글꼴이 없으면 대체 글꼴). 편집·미리보기용으로 쓰고, 학습·평가 데이터는 서버나 도커에서 만든다.

### ⑥ 새 데이터셋 생성과 자동 등록

1. **새로 만들기**에서 레시피·결과 이름·프로세스 수를 정해 `만들기`를 누릅니다.
2. 같은 화면의 **데이터셋 생성 현황**에서 생성·등록 상태를 봅니다. 작업 이름을 누르면 상세 로그를 볼 수 있습니다.
3. 생성과 등록이 끝나면 아래 **등록된 데이터셋** 목록에 자동으로 추가되고 `새로 등록됨`으로 표시됩니다. 폴더 경로를 다시 등록할 필요가 없습니다.
4. 결과 링크로 설명서·문항·업무 묶음을 엽니다. 은행 업무, 합성 OCR, 가져온 이미지에서 만든 OCR 세트에 같은 자동 등록을 적용합니다.

서버 재시작으로 완료 처리가 누락돼도 ⑥을 열거나 목록을 갱신하면 **작업 기록에 있는 완성 결과**를 확인해 등록합니다. 은행 업무는 `meta.json`·`dataset.json`과 문항 수, OCR은 `prepared/DONE.json`·`pages.jsonl`로 완료 여부를 확인합니다. 미완성·생성 실패·취소 작업은 완료로 등록하지 않습니다. 같은 폴더는 중복 등록하지 않으며 기존 데이터셋의 고정 상태도 유지합니다. 외부 명령줄로 만든 폴더는 기존 `폴더 등록`을 사용합니다. 상세 설계는 [DESIGN.md](DESIGN.md) 9.1.1.

### 내가 가진 데이터로 시작하기

**라벨 있는 데이터는 생성기의 원본 라벨 형식으로 고정한다.** `labels/<id>.json`에 `id`, `doc_type`, `doc_name`, `images`, `pages`, `fields`를 준비한다. 원본의 `page`는 **0부터**, `bbox`는 **이미지 픽셀**이다. 모델 정답의 `page` 1부터·`bbox_2d` 0~1000과 구분한다. 규격은 [LABEL_FORMAT.md](LABEL_FORMAT.md), 기계용 규격은 [document.schema.json](static/label-format/v1/document.schema.json), 실제 합성 이미지와 라벨은 [예제 ZIP](static/label-format/v1/example.zip)이다. ④ 가져오기에서도 다운로드한다. **ZIP은 먼저 압축을 풀고 폴더 경로를 입력한다.**

1. `meta.json`, `images/`, `labels/`를 한 폴더에 둔다. `meta.json`의 `format`은 `docgen-labels/1`, `gt`는 `reviewed`/`pseudo`/`exact`, `real_data`는 실서류 여부다. 생성 폴더도 이 반입 메타 파일을 추가한다.
2. **④ 가져오기 → 라벨 있는 데이터 → 폴더 경로 → 폴더 검사**를 누른다. 서버/컨테이너에서 실행 중이면 서버가 읽을 수 있는 경로를 입력한다. `import_dir`이 설정돼 있으면 그 아래만 허용한다.
3. 오류가 있으면 표시된 파일·항목을 고쳐 다시 검사한다. 사전에 없는 새 항목 키는 확인 사항으로 표시하고, 미등록 서식 ID는 등록 전까지 오류로 처리한다. 이미지·정답 미리보기에서 쪽과 위치를 확인한다.
4. 이름·종류(은행 업무/OCR)·용도(평가/학습)·과제를 고르고 확인란을 체크한 뒤 **데이터셋 만들고 등록**을 누른다. ⑥으로 이동해 진행을 보고 완료 후 아래 목록에서 연다.

은행 업무는 `classify`, `kie`, `marks`, `ocr_field`, 묶음의 `doc_check`·`review`를 지원한다. ③에 저장한 직접 추출·비교 작업과 기존 계산 규칙을 적용하며 입력이 부족한 작업은 사유를 남긴다. `bundles.jsonl`의 `not_customer`(없으면 명의 미확인으로 구비 문항 생략)에 타인 서류 ID 목록 또는 `[]`를 적는다. 실서류에 합성 변조 대조 사례를 적용하거나 합성 고객 프로필을 만들지 않는다. 항목 라벨만으로 쪽 전체 OCR 정답을 추정하지 않는다.

OCR 종류는 모든 쪽의 `ocr/*.json`과 **`meta.json`의 `ocr_scope: "full_page"`**가 있을 때만 선택할 수 있다. 예제의 OCR은 값 칸·항목명 일부라 은행 업무 생성에 사용하고 쪽 전체 OCR 세트로 내보내지 않는다. OCR 학습용은 학습/평가 분리를 위해 문서 2건 이상이 필요하다. 입력 원본은 읽기만 하고, 해시로 검사 후 변경을 감지하며, 출력의 `input/`에 원본을 복사해 경로가 나중에 바뀌어도 데이터셋이 유지되게 한다.

| 목적 | 준비 | 현재 UI 순서·지원 범위 |
|---|---|---|
| 실제 이미지·PDF로 OCR 데이터셋 | 문서별 파일. 여러 쪽은 문서 하나당 PDF 하나 | ④ 가져오기 → ⑤ OCR 검수·확인 → ④ OCR 벤치마크로 → ⑥ 자동 등록 |
| 내 서식을 합성 데이터에 추가 | 견본 문서, 가능하면 같은 양식에 값이 다른 문서 둘 이상 | ④ 포맷 열기 → 템플릿 만들기 → ① 영역·키·값 출처 편집·검수 → ③ 시나리오 → ⑥ 생성 |
| 실제 문서의 항목 정답으로 데이터셋 | 생성기와 같은 `labels/*.json` + 문서 이미지 | ④ 라벨 있는 데이터 → 검사·미리보기·확인 → ⑥ 자동 등록. 라벨 수정은 원본 JSON에서 |
| 실제 고객의 서류로 구비·직접 비교·계산 | 표준 라벨 + 접수별 `bundles.jsonl` + 시나리오 | 문서 연결을 읽어 저장된 처리 설정 적용. 구비는 명의 확인 목록 필요. 합성 변조 대조 사례 미적용 |

파일 배치 예시, OCR 설정, 항목 JSON, Q/A 준비 범위는 [DATA_IMPORT.md](DATA_IMPORT.md)에 정리했다. ⑨는 적용 설정을 보는 화면이며, OCR 연결·저장 경로는 `studio/config.json`에서 설정한다. 이미지 폴더 옆에 OCR JSON을 두기만 해서는 현재 가져오기가 그 JSON을 읽지 않는다.

**고친 것이 저장되는 곳** (모두 저장소 안 파일, git diff 로 검토)

| 고친 것 | 파일 | 생성기가 읽는 곳 |
|---|---|---|
| overlay 영역·키·값 출처·배경 지우기 | `add_template/overrides/<ID>.json` (가져온 서식 `img_*` 는 그 서식 폴더의 `overrides.json`) | `docgen/overrides.py` → `docgen/realform.py` |
| 가져온 서식 (공개 서식 묶음) | `add_template/images/img_*/` (`layout.json`, `page_<n>.png`) — 실서류 묶음에서 만든 것은 `private_forms_dir/img_*/` (저장소 밖) | `docgen/realform.py` `register_images` |
| 검수·배정·메모·문제 표시 | `docgen/catalog.json` | `docgen/bench/build.py` (학습 데이터에서 평가 전용 서식 빼기) |
| 표시 요소 확률 | `docgen/marks.json` | `docgen/marks.py` |
| 표시 요소 풀 | `assets/marks/pools.json`, `assets/marks/<풀>/` | `docgen/marks.py` → `realform.py`·`render.py` |
| 표준 키 사전 (자동 생성) | `docgen/keys.json` (`python scripts/build_keys.py`) | studio 의 키 고르기 |

저장소 밖에 두는 것: 가져온 묶음(`<workspace>/imports/<묶음>/`: `batch.json`, `pages.jsonl`, `formats.json`, 썸네일), OCR 캐시(설정 `ocr.cache_dir`, 기본 `studio_cache/ocr`), OCR 검수본(`real_data_dir/ocr_reviewed/`, 설정이 없으면 `<workspace>/real_data/` 에 두고 화면에 경고).

가져온 서식은 등록되자마자 목록·편집기에 나오지만, **검수 완료 전에는 레시피의 `"all"`·그룹 선택으로 데이터셋에 들어가지 않는다** (값을 덜 지운 견본 배경이 생성 이미지마다 복제되지 않게). 서식 ID 를 직접 적으면 시험용으로 들어간다.

기본값은 예전 생성기와 같아서 아무것도 고치지 않으면 생성 결과(라벨·이미지)가 그대로다 (2026-10-20, overlay·html 서식 10종 × seed 3개로 확인).

메뉴는 일의 흐름 순서다: ① 서식 → ② 표시 요소 → ③ 시나리오·묶음 (합성 재료) → ④ 가져오기 → ⑤ 검수 (실서류·기존 결과) → ⑥ 데이터셋 → ⑦ 평가 (두 벤치마크를 출처와 상관없이 같은 화면에서) → ⑧ 작업 → ⑨ 설정.

미리보기는 `studio_cache/preview/` 에 저장된다(git 제외). 서식 파일(템플릿·생성 함수·레이아웃)이나 공통 렌더링 코드가 바뀌면 자동으로 다시 그린다. 렌더링 코드는 [docgen/preview.py](../docgen/preview.py).
