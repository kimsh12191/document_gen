# OCR·은행업무 벤치마크

docgen이 만드는 합성 서류로 **고정된 평가 세트**를 만들고, 모델을 돌리고, 채점합니다. 코드는 [docgen/bench/](../docgen/bench/)에 있습니다.

- **OCR:** 글자를 읽는 능력
- **문서 이해:** 서류를 알아보고 값을 뽑는 능력
- **은행 업무:** 고객 한 명이 낸 서류 묶음을 보고 심사 담당자처럼 판단하는 능력

이 세 가지를 따로 잽니다.

```bash
# 1) 평가 세트 만들기 (기본: 서류 476종 x 1건 + 업무 12종 x 고객 4명, 약 20~30분)
python -m docgen.bench build --out bench_out

# 2) 모델 돌리기 — OpenAI 호환 API (vLLM, SGLang, LMDeploy 서버 등)
vllm serve Qwen/Qwen2.5-VL-7B-Instruct --port 8000 --limit-mm-per-prompt image=16
python -m docgen.bench run --bench bench_out --pred preds/qwen25vl7b \
    --base-url http://localhost:8000/v1 --model Qwen/Qwen2.5-VL-7B-Instruct --workers 8

# 3) 채점 → preds/qwen25vl7b/report.md, report.json
python -m docgen.bench eval --bench bench_out --pred preds/qwen25vl7b

# 모델 여러 개 비교표
python -m docgen.bench eval --bench bench_out --pred preds/model_a --pred preds/model_b
```

- **빠른 점검:** `run --limit 20`이면 과제마다 앞 20문항만 돌립니다.
- **이어서 돌리기:** 중단되거나 오류가 난 문항은 같은 명령을 다시 실행하면 그것만 다시 보냅니다.
- **예측 없음·파싱 실패:** 0점으로 셉니다(CER은 1). 빈 답이 빈 칸(null)이나 "도장 없음"을 우연히 맞히지 않게 하려는 것입니다. 보고서에 건수가 따로 나옵니다.
- **채점기 점검:** `run --oracle`은 정답을 그대로 출력으로 씁니다. 이때 모든 과제가 100점이어야 합니다.

## 과제

| 영역 | 과제 | 입력 → 출력 | 주 지표 |
|---|---|---|---|
| OCR | `ocr_field` | 값 칸 하나를 잘라낸 이미지 → 적힌 글자 | 완전 일치율 (CER 함께 보고) |
| OCR | `ocr_page` | 서류 전체(여러 쪽) → 전체 받아쓰기 | 값 재현율: 정답 값이 받아쓴 글에 들어 있는 비율 |
| 문서 이해 | `classify` | 서류 → 서류명 | 정확도 |
| 문서 이해 | `kie` | 서류 + 항목 목록(키·항목명) → 값 JSON | F1 (항목 정확도, 서류 전체 일치율 함께) |
| 문서 이해 | `marks` | 서류 + 체크박스·도장·서명 목록 → 상태 JSON | 항목 정확도 |
| 은행 업무 | `doc_check` | 업무명 + 필수 서류 목록 + 제출 서류 첫 쪽들 → 빠진 서류 | 완전 일치율 (F1 함께) |
| 은행 업무 | `cross_check` | 서류 2~4건 → 서로 맞지 않는 값과 그 서류 | 종합 점수 (탐지·위치·오탐률 함께) |
| 은행 업무 | `review` | 심사 질문 + 관련 서류 → 숫자 또는 예/아니오 | 정확도 |

### OCR

- **`ocr_field`:** 서류마다 값 칸 6개를 골라 잘라냅니다(위아래 여백 포함).
  - 결과는 글씨(`print` 인쇄체 / `hand` 손글씨), 촬영 조건, 값 종류(이름·주민번호·금액·날짜·주소 …), 손글씨 정정 여부로 나눠 봅니다.
  - 손글씨는 하나은행 원본 서식(`hf*`)에서 나옵니다.
- **`ocr_page`:** 전체 정답 글자가 없어서 "문서에 적힌 값이 받아쓴 글에 들어 있는가"로 잽니다.
  - 공백은 무시합니다.
  - `recall_fuzzy`는 값 길이의 20%까지 글자가 틀려도 찾은 것으로 셉니다.
  - 서식의 고정 문구(항목명, 안내문)는 채점하지 않습니다.

### 문서 이해

- **`classify`:** 서류명을 자유롭게 답하게 하고, 공백·문장부호를 뺀 뒤 정식 명칭과 같으면 맞습니다.
  - `acc_lenient`는 답 안에 정식 명칭이 들어 있으면 맞은 것으로 셉니다.
- **`kie`:** 항목 키와 항목명을 질문에 같이 줍니다. 그래서 학습하지 않은 모델도 같은 조건으로 잴 수 있습니다.
  - 키가 많은 서류는 40개까지만 묻습니다.
  - 빈 칸은 `null`이 정답입니다.
  - 값은 **타입에 맞춰 비교**합니다.
    - 날짜: `2025년 9월 20일` = `2025-09-20`
    - 금액: `금 오억원정 (₩500,000,000)` = `500000000`, `327,000,000원` = `327,000,000`. 1원만 달라도 틀립니다.
    - 번호(전화·주민·계좌): 숫자만 비교
    - 그 밖: 공백·문장부호 무시
  - 중첩 JSON(`{"loan": {"amount": ...}}`)으로 답해도 점 경로로 펴서 채점합니다.
- **`marks`:** 체크된 보기 글자, 복수 선택 목록, 도장·서명 true/false를 맞힙니다.

### 은행 업무 (업무 묶음)

시나리오 12종([README](../README.md#사용법))마다 고객 4명분 서류 묶음을 만듭니다. 묶음 서류는 모두 현행 하나은행 서식이라 날짜가 서로 맞습니다.

- **`doc_check` — 서류 구비 확인**
  - 필수 서류 중 0~2건(30/50/20%)을 빼고 나머지 첫 쪽만 순서를 섞어 줍니다.
  - 빠진 서류명을 목록 그대로 답해야 합니다. 비슷한 이름은 목록의 서류에 대응시켜 채점합니다.
- **`cross_check` — 서류 간 대조**
  - 짝수 번째 묶음은 **변조 문항**입니다.
    - 여러 서류에 같이 나오는 값(성명, 주민번호, 생년월일, 주소, 연락처, 계좌, 상호, 사업자번호, 금액) 하나를 한 서류에서만 그럴듯하게 바꿉니다.
    - 바꾸는 방식: 이름 한 글자, 번호 한 자리, 금액 앞자리, 날짜 며칠.
    - HTML의 그 칸 글자만 바꿔 다시 렌더링합니다. 그래서 바뀐 서류는 값 하나 말고는 원본과 똑같습니다. 촬영 증강도 원본과 같게 들어갑니다.
  - 홀수 번째 묶음은 바꾸지 않은 **정상 문항**입니다.
  - 채점
    - 정상 문항: "일치(consistent: true)"라고 하면 맞습니다.
    - 변조 문항: 불일치라고 하고, **바뀐 서류**와 함께 **그 값 또는 항목명**을 짚어야 맞습니다.
    - 탐지 정확도, 위치 정확도, 오탐률(정상 문항을 불일치라고 한 비율)을 따로 보고합니다.
- **`review` — 심사 질의:** 정답은 서류 정답값으로 계산합니다. 질문에 반올림 자릿수와 기준일을 적어 답이 하나로 정해집니다.

| 규칙 | 시나리오 | 질문 | 능력 |
|---|---|---|---|
| `ltv` | 주택담보 | 대출신청금액 ÷ 매매대금 (%) | 계산(비율) |
| `collateral_ratio` | 주택담보 | 채권최고액 ÷ 약정 대출금액 (%) | 계산(비율) |
| `jeonse_ratio` | 전세자금 | 대출신청금액 ÷ 임차보증금 (%) | 계산(비율) |
| `income_multiple` | 신용대출 | 대출신청금액 ÷ 원천징수 급여 합계 (배) | 계산(비율) |
| `age` | 신분증 + 신청서가 있는 업무 | 신청일 기준 만 나이 (주민번호로) | 날짜 계산 |
| `tenure` | 대출 | 입사일~신청일 만 재직연수 | 날짜 계산 |
| `doc_valid` | 발급일이 있는 서류가 있는 업무 | 발급 후 90일 이내인가 (예/아니오) | 날짜 계산 |
| `net_pay` | 신용대출 | 급여명세서 지급액계 − 공제액계 | 계산(합계) |
| `sales_rest` | 주택담보 | 매매대금 − 계약금 − 중도금 | 계산(합계) |
| `invoice_sum` | 해외송금 | 상업송장 품목 금액 합계 | 표 계산 |
| `tuition_due` | 유학생 송금 | 이전 잔액 + 청구액 − 납부액 | 계산(합계) |
| `debt_ratio` | 법인 여신 | 부채총계 ÷ 자본총계 (%) | 표 계산 |

`doc_valid`는 묶음 서류의 발급일이 대개 신청일과 같아 답이 늘 "예"가 됩니다. 그래서 절반은 발급일을 93~400일 앞당긴 사본을 만들어 묻습니다. 나머지 절반은 0~88일 전으로 옮깁니다.

## 평가 세트

- **고정 seed:** 같은 설정이면 언제 만들어도 같은 세트가 나옵니다(같은 코드 기준).
  - 단일 서류 과제는 고객 seed `1,000,000`부터, 업무 묶음은 `2,000,000`부터 씁니다.
  - 학습 데이터(`python -m docgen generate --seed 0 …`)와 겹치지 않게 하려는 것입니다. **학습에는 seed 1,000,000 미만을 쓰세요.**
- **촬영 조건:** 서류마다 깨끗한 원본 50%, 스캔 20%, 촬영 15%, 팩스 15%입니다. 위치 정답은 증강에 맞춰 옮깁니다.
- **기록:** `meta.json`에 만든 설정, 생성기 커밋, 과제별 문항 수가 남습니다. 결과를 비교할 때는 같은 `meta.json`의 세트인지 확인하세요.

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--types` | all | 단일 서류 과제에 쓸 서류 (ID, 그룹명) |
| `--per-doc` | 1 | 서류 종류마다 샘플 수 |
| `--scenarios` | all | 업무 묶음 과제에 쓸 시나리오 |
| `--bundles` | 4 | 시나리오마다 고객 수 (짝수 번째 = cross_check 변조) |
| `--fields-per-doc` | 6 | 서류마다 `ocr_field` 문항 수 |
| `--max-keys` | 40 | `kie`·`marks` 한 문항에 묻는 최대 항목 수 |
| `--scale` | 2.0 | 이미지 배율 (A4 한 쪽 약 1588×2246) |

### 문항 형식 (`tasks/<과제>.jsonl`)

```json
{"id": "kie/loan_application_1000000", "task": "kie",
 "images": ["images/loan_application_1000000.jpg"],
 "prompt": "이 문서에서 아래 항목의 값을 찾아 JSON 객체로 답하세요. …\n- applicant.name: 성명\n- loan.amount: 대출신청금액 …",
 "answer": {"applicant.name": "김나우", "loan.amount": "56,000,000"},
 "eval": {"fields": {"loan.amount": {"type": "amount", "norm": 56000000, "kind": "amount"}}},
 "meta": {"doc_type": "loan_application", "group": "bank_form", "condition": "scan", "writing": "print", "n_pages": 1}}
```

- `images`는 세트 폴더 기준 상대 경로이고, 질문 앞에 순서대로 넣습니다.
- `answer`는 정답이고, `eval`은 채점에 쓰는 추가 정보입니다.
- 다른 실행기(사내 추론 서버, ms-swift `infer` 등)를 쓰려면 예측을 `{"id": 문항 id, "output": "모델 출력"}` 꼴로 `<pred 폴더>/<과제>.jsonl`에 저장한 뒤 `eval`을 돌리면 됩니다.

### 실행 옵션 (`run`)

| 옵션 | 뜻 |
|---|---|
| `--base-url`, `--model` | OpenAI 호환 서버 주소와 모델 이름 |
| `--api-key-env` | API 키를 읽을 환경변수 (기본 `OPENAI_API_KEY`) |
| `--max-side` | 이미지 긴 변을 이 픽셀 이하로 줄여 보냄 (토큰·비용 조절) |
| `--workers` | 동시 요청 수 |
| `--tasks` | 일부 과제만 (`kie,review`) |
| `--limit` | 과제마다 앞 N 문항만 |
| `--system` | 시스템 프롬프트 |

업무 묶음 문항은 이미지가 여러 장입니다(`doc_check`는 최대 12장, `cross_check`는 최대 10장). vLLM은 `--limit-mm-per-prompt image=16`처럼 한 요청의 이미지 수를 늘려 주세요.

## 해석할 때 주의

- **합성 서류입니다.** 서식·글꼴·증강이 실제 스캔본보다 단순합니다. 실제 서류 성능의 상한에 가깝게 보고, 실제 표본으로 따로 확인하세요.
- **학습 데이터와 같은 생성기입니다.** docgen으로 학습한 모델은 서식 분포를 이미 봤으므로 점수가 유리하게 나옵니다. 범용 모델과 비교할 때 이 점을 적어 두세요.
- **`ocr_page`는 값만 셉니다.** 서식 고정 문구를 잘 읽어도 점수에 들어가지 않습니다.
- **`kie`는 항목명을 알려 줍니다.** "어떤 항목이 있는지 찾는" 능력은 재지 않습니다.
