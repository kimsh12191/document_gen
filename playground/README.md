# 모델 써 보기 (playground)

학습한 모델에 그림 한 장(또는 여러 쪽)을 넣고, 벤치마크와 같은 질문을 고르거나 고쳐서 물어 답을 눈으로 봅니다.
점수는 내지 않습니다. 점수는 평가 세트로 봅니다 ([guide/eval.md](../guide/eval.md)).

**GPU 학습 컨테이너**에서 띄웁니다. 그 컨테이너 안에서 모델(vLLM)을 띄우고 내리기 때문입니다.
실서류 이미지도 이 컨테이너 안의 모델로만 갑니다.

```bash
cd <저장소>
python -m playground --port 7860                   # 이 서버 안에서만 열림: http://127.0.0.1:7860
python -m playground --port 7860 --open            # 다른 PC 의 브라우저에서 http://<GPU서버>:7860
```

- 이 화면은 명령을 실행할 수 있어서 기본은 서버 안에서만 열립니다. 내 PC 에서 보려면 `--open` 을 쓰거나 `ssh -L 7860:127.0.0.1:7860 <GPU서버>` 로 연결합니다.
- 컨테이너의 포트(7860)가 밖으로 열려 있어야 `--open` 으로 열립니다 (`docker run -p 7860:7860` 또는 host network). 안 열리면 ssh 방법을 씁니다.
- 새로 깔 것은 없습니다 (표준 라이브러리 + Pillow, 학습 컨테이너에 이미 있는 것). 화면은 외부 CDN 을 쓰지 않습니다.
- 화면을 꺼도 띄운 모델은 계속 떠 있습니다. 다시 켜면 목록에 나옵니다. 끄려면 화면에서 [내리기].

## ① GPU·모델

1. **GPU 표**: `nvidia-smi` 로 번호·메모리·사용률을 5초마다 보여 줍니다.
   - "비어 있음": 보이는 프로세스가 없고 메모리를 1GB 안 쓰는 GPU.
   - 컨테이너 안에서는 다른 컨테이너의 프로세스가 안 보일 수 있어서, 프로세스가 안 보여도 메모리를 쓰면 "사용 중"입니다.
   - 이 화면이 띄운 모델이 쓰는 GPU 는 그 모델 이름이 나옵니다.
2. **GPU 고르기**(표의 체크) → **모델 경로** 적기 → **실행할 명령**이 만들어집니다.
   - 기본은 학습 평가 때와 같은 `swift deploy` 명령입니다 (`train/pipeline.py` 의 `eval.deploy_command`, `IMAGE_MAX_TOKEN_NUM` 도 같은 계산).
   - GPU 를 둘 이상 고르면 `--vllm_tensor_parallel_size` 가 붙습니다.
   - **LoRA 체크포인트**(`adapter_config.json` 이 있는 `checkpoint-*`)면 평가 때처럼 먼저 합칩니다: `swift export … --output_dir <체크포인트>-merged && swift deploy …`. 출발 모델 경로는 `args.json` 에서 읽습니다. 합친 폴더가 이미 있으면 바로 띄웁니다.
   - 방식 `vllm serve` 로 바꿀 수 있습니다. 포트는 학습 평가(8000~)와 겹치지 않게 8100 부터 빈 것.
3. 명령은 **고쳐도 됩니다**. [띄우기] 를 누르면 보이는 글자 그대로 `bash` 로 실행합니다. 고친 뒤 위 입력을 바꾸면 덮어쓰지 않고 [명령 다시 만들기] 를 띄웁니다.
4. **떠 있는 모델**: 상태(준비 중 몇 분 / 준비됨 / 끝남), [로그], [내리기].
   - 준비됨 = `/v1/models` 가 답함. 처음 뜰 때 몇 분~수십 분 걸립니다.
   - `swift deploy` 는 포트가 막혀 있으면 다음 포트로 뜹니다. 로그의 실제 포트를 읽어 따라갑니다.
   - [내리기] 는 swift 가 띄운 vLLM 작업 프로세스까지 끕니다 (20초 안에 안 꺼지면 강제로).
   - 이미 떠 있는 서버는 주소(`http://…:8000/v1`)로 붙을 수 있습니다.

## ② 써 보기

1. 위쪽 **묻는 모델**을 고릅니다. 둘 이상이면 같은 질문을 모두에게 보내 답을 나란히 놓습니다 (예: 출발 모델과 SFT 모델).
2. **이미지 폴더**를 열고 그림을 누릅니다 (하위 폴더 포함, png·jpg·tif(여러 쪽은 쪽마다)·bmp·webp).
   - Ctrl(⌘) 누르고 누르면 여러 장을 고릅니다. 고른 순서가 쪽 순서입니다 (`kie`·`ocr_page` 처럼 서류 전체를 묻는 과제).
3. **질문 고르기**: 벤치마크와 같은 문장이 질문 칸에 채워집니다. 그대로 묻거나 고쳐서 묻습니다. [원래 질문으로] 로 되돌립니다.

| 고르는 질문 | 화면에서 정할 것 | 보내는 그림 |
|---|---|---|
| `ocr_page` 전체 받아쓰기, `spotting` 모든 글자와 위치 | 없음 | 고른 그림 |
| `crop_ocr`·`ocr_field` 잘라서 읽기 | 그림에서 네모 끌기 | 그 부분만 자른 것 |
| `bbox_ocr`·`region_ocr` 좌표 영역 | 그림에서 네모 끌기 (질문에 0~1000 좌표) | 고른 그림 |
| `grounding` 이 글자는 어디에 | 찾을 글자 | 고른 그림 |
| `relation` 기준 글자 옆 | 기준 글자(또는 기준에 네모) + 방향 | 고른 그림 |
| `marked_ocr`·`marked_box` 그린 상자 | 색 고르고 네모 끌기 (색마다 하나, 셋까지). "좌표도 같이 적기" | 상자를 벤치마크와 같은 굵기·여백·색으로 그린 것 |
| `classify` 서류 분류 | (서식을 고르면 그 서식의 질문) | 고른 그림 |
| `kie` 값 뽑기, `marks` 체크·도장·서명 | 서식 → 그 서식의 항목 목록이 들어감 (벤치마크처럼 앞 40개, 0 이면 전부). 안 고르면 항목 줄을 직접 | 고른 그림 |
| `freetext` 기타 칸 정리 | 칸 이름·기준일 | 고른 그림 |
| 직접 쓰기 | 빈칸 | 고른 그림 |

   - OCR 질문은 한국어·영어 두 문장이 있습니다 (벤치마크도 둘 다).
   - 서식의 항목 목록은 `guide/fields/fields.json`(자동 생성 카탈로그)에서 읽고, 서식 폴더의 `questions.json`·`fields.json` 의 `q`(묻지 않기·항목명)를 따릅니다.
4. **[묻기]**. "평가와 같은 크기로 줄여 보내기"(기본 켬)는 평가 세트를 만들 때처럼 그림을 줄입니다 (`train/mix.py` 의 `image_max_size`, 여러 장이면 한 질문의 그림 몫을 나눔). 끄면 원본 크기로 보냅니다.
   - 요청도 평가와 같습니다: `temperature`·`max_tokens`·`enable_thinking` 은 `train/configs/inference.json`, 그림을 질문 앞에.
5. **답**: 모델마다 원래 답, JSON 으로 읽은 결과, 걸린 시간, 보낸 그림.
   - JSON 으로 답하는 과제(`spotting`·`grounding`·`relation`·`marked_box`·`kie`·`marks`·`freetext`)인데 못 읽으면 "형식 오류".
   - `max_tokens` 에서 끊기면 "길이 한도에서 끊김".
   - 답에 `bbox_2d` 가 있으면 큰 그림과 보낸 그림 위에 모델별 색으로 그립니다 (`page` 로 쪽을 찾음).
6. **이어서 묻기**: 같은 그림으로 앞의 질문·답을 함께 보내 대화를 잇습니다. 그림이나 질문 종류를 바꾸면 새 대화.

## 남는 것 (`--home`, 기본 `~/.docgen_playground`)

| | |
|---|---|
| `models.json` | 띄운 모델·붙은 서버 목록 (화면을 다시 켜면 읽음) |
| `logs/<시각>-<id>.log` | 모델 서버 로그 (맨 위에 실행한 명령) |
| `log.jsonl` | 묻고 받은 기록: 시각, 과제, 질문, 그림 경로, 모델·경로, 답, 보낸 그림 이름 |
| `sent/` | 실제로 보낸 그림 (자르거나 상자를 그리거나 줄인 것) |
| `recent.json` | 최근 쓴 모델 경로·이미지 폴더 |

## 안 하는 것

- 점수 매기기: 정답이 없는 그림이라 눈으로 봅니다. 점수는 평가 세트로.
- 업무 묶음 과제(`doc_check`·`cross_check`·`review`): 서류 여러 건이 필요해서 고르기 목록에 없습니다. "직접 쓰기"에 질문을 붙여 넣고 그림을 여러 장 고르면 물어볼 수는 있습니다.
- 사내 OCR 결과와 나란히 보기: 사내 OCR 연결은 studio 쪽에 있습니다.

## 코드

| 파일 | |
|---|---|
| `__main__.py` | `python -m playground` |
| `server.py` | 웹 서버·API (`/api/gpus`, `/api/models…`, `/api/folder`, `/api/question`, `/api/ask`) |
| `gpus.py` | `nvidia-smi` 읽기 |
| `models.py` | 명령 만들기, 띄우기·상태·내리기 |
| `questions.py` | 고를 수 있는 질문 (docgen 의 벤치마크 문장을 읽기만) |
| `images.py` | 폴더 보기, 자르기·상자 그리기·크기 줄이기 |
| `ask.py` | 묻기, 답 읽기, 기록 |
| `static/` | 화면 (html·js·css, 외부 파일 없음) |
| `tests/` | `python -m pytest playground/tests` (GPU·vLLM 없이, `tests/fake_vlm.py` 가 모델 서버 흉내) |

다른 폴더(`docgen/`, `train/`)는 읽기만 합니다. 이 폴더를 고치거나 지워도 생성·학습·서식에는 영향이 없습니다.
