# 은행 업무 Viewer: 모델 답을 문항별로 확인

은행 업무 파이프라인(`run_bank_pipeline.py`)의 결과를 문항 하나씩 보는 웹 화면입니다. 추가 설치는 필요 없습니다. PDF를 열 때만 `pypdfium2` 또는 `PyMuPDF`가 필요합니다.

- **벤치마크 보기:** 출발(OCR) 모델·SFT·GRPO 모델이 같은 문항에 낸 답을 정답과 나란히 봅니다. 서류 이미지와 점수도 함께 나옵니다.
- **직접 테스트:** 내 서류 파일을 올려 서류 구비 확인·서류 대조·심사 질의·정보 추출을 물어봅니다.

1부 OCR 모델의 글자·위치를 보는 **OCR viewer**는 [ocr/viewer/README.md](../../ocr/viewer/README.md)에 있습니다.

| 파일 | 역할 |
|---|---|
| `bank_start.sh` | (모델 폴더를 주면) 모델 서버와 화면을 한 번에 띄웁니다. Ctrl+C를 누르면 둘 다 꺼집니다. |
| `bank_viewer.py` | 화면을 띄우는 프로그램입니다. 저장된 답을 읽어 채점하고, 모델 서버에 질문을 보냅니다. |
| `bank.html` | 화면 자체입니다. 고친 뒤 브라우저를 새로고침하면 바로 반영됩니다. |
| `bank-model-server.log` | `bank_start.sh`가 띄운 모델 서버의 로그입니다. 실행하면 생깁니다. |

`bank_viewer.py`는 다른 폴더의 코드를 그대로 씁니다: `bank/bank_task`(이미지 크기 규칙, 채점), `ocr/`의 `bank_ocr`와 OCR viewer의 PDF 그리기, 그리고 채점기가 든 docgen 코드(설정의 `data.docgen_root`, 기본은 저장소 최상위).

## 1. 띄우기

`bank/` 폴더에서 실행합니다. 설정은 파이프라인과 같은 `configs/bank_pipeline.json`을 읽어, 준비된 데이터(`data.output_dir`)와 저장된 모델 답(`workdir`의 `reports/`)을 찾습니다.

```bash
cd bank

# 저장된 답만 보기: GPU가 필요 없어서 학습 중에도 됩니다
bash viewer/bank_start.sh

# 모델과 함께 (다시 풀기·직접 테스트): 파이프라인이 병합해 둔 모델 폴더와 GPU 번호
ls runs/bank1/merged/
bash viewer/bank_start.sh runs/bank1/merged/sft-<버전>-checkpoint-<번호> 1
```

- **설정 바꾸기 (환경변수):**
  - 다른 설정 파일: `CONFIG=configs/다른설정.json`
  - 리허설(`--smoke`) 결과 보기: `SMOKE=1`
  - 포트: `MODEL_PORT=8011 VIEW_PORT=7861` (기본값)
  - 다른 PC에서 서버 IP로 열기: `VIEW_HOST=0.0.0.0`
- **모델 서버 설정:** 파이프라인 평가와 같습니다. 질문당 이미지 최대 16장, 이미지 한 장 3600토큰, 답 최대 4096토큰입니다. 모델을 불러오는 데 1~3분 걸립니다.
- 모델이 이미 `MODEL_PORT`에 떠 있으면 새로 띄우지 않고 그 모델을 씁니다.

## 2. 브라우저로 열기

OCR viewer와 같습니다([ocr/viewer/README.md](../../ocr/viewer/README.md) 2번). 포트만 `7861`입니다. VS Code라면 **PORTS** 탭에서 `7861`을 포워딩하고 `http://localhost:7861`을 엽니다.

## 3. 벤치마크 보기

1. 왼쪽에서 거를 조건을 고르고 **목록 보기**를 누릅니다.
   - **과제·업무:** 예: 서류 대조 + 전세자금대출
   - **서류 대조:** 불일치 분류, 사례, 변조 문항/정상 문항
   - **심사 질의:** 능력(계산, 날짜 계산, 서류 대조 등)
   - **모델:** 특정 모델이 틀린 문제(또는 맞은 문제)만
   - **맞힌 모델 / 틀린 모델:** 앞 모델은 맞히고 뒤 모델은 틀린 문제만. 예를 들어 맞힌 모델 = SFT, 틀린 모델 = 출발 모델이면 학습으로 좋아진 문제를 봅니다. 반대로 고르면 나빠진 문제를 봅니다.
2. 목록 위에 거른 문항들에 대한 모델별 평균 점수와 정답률이 나옵니다. 목록의 1, 2, 3…은 그 표의 모델 번호이고, ✓ 정답, ✗ 오답, 숫자는 부분 점수입니다.
3. 문항을 누르면 오른쪽에 나옵니다. 키보드 ← → 로 이전·다음 문항으로 넘어갑니다.

| 오른쪽 화면 | 내용 |
|---|---|
| 모델별 점수 | 0~1 점수(GRPO 보상과 같은 채점, 1이 정답), 그 과제의 주 지표, 답 형식 오류 여부 |
| 정답과 모델 답 | 정보 추출·체크는 항목별로 정답·모델 값을 나란히(초록 맞음, 빨강 틀림). 서류 대조는 판단과 짚은 서류·항목·값. 서류 구비 확인은 빠진·불필요·타인 서류 목록 |
| 서류 이미지 | 모델이 본 크기 그대로. 누르면 크게 보입니다. 서류 이름과 쪽, 바꾼 사본이면 표시(다른 고객 서류, 발급일 바뀜, 값을 바꾼 사본) |
| 질문 전문, 모델 원문 답 | 접어 둔 칸을 열어 봅니다 |
| 지금 모델 서버로 다시 풀기 | 모델과 함께 띄웠을 때만. 지금 띄운 모델로 이 문항을 다시 풀고 채점합니다 |

## 4. 직접 테스트

**직접 테스트** 탭에서 서류 파일을 올리고 과제를 고른 뒤 **실행**을 누릅니다. 모델과 함께 띄웠을 때만 됩니다.

| 과제 | 올릴 파일 | 채울 칸 |
|---|---|---|
| 서류 구비 확인 | 서류마다 파일 하나 (첫 쪽만 보냄) | 고객 성명, 업무, 필수 서류 목록 (업무를 목록에서 고르면 자동으로 채워짐) |
| 서류 대조 | 대조할 서류 2~3건 (모든 쪽) | 고객 성명, 업무 |
| 심사 질의 | 질문에 필요한 서류 | 업무, 질문 (답 형식을 적어 주면 좋음: "숫자만", "예/아니오") |
| 정보 추출 | 서류 한 건 | 뽑을 항목 (한 줄에 하나) |
| 서류 분류, 전체 받아쓰기 | 서류 한 건 | 없음 |
| 직접 질문 | 아무 서류 | 질문 |

- **질문 문장:** 벤치마크와 같은 문장으로 묻습니다. 그래서 학습한 형식 그대로 답이 나옵니다. 과제별 질문 문장과 답 형식은 [guide/questions.md](../../guide/questions.md)에 있습니다.
- **이미지 크기:** 학습 때와 같은 규칙으로 줄입니다. 한 장은 최대 3600토큰이고, 한 질문의 이미지 합이 12000토큰을 넘지 않게 장마다 같은 비율로 줄입니다. 한 번에 16장까지 보낼 수 있습니다.
- **PDF:** 200 DPI로 그림으로 바꿉니다. 여러 쪽 PDF·TIF는 쪽마다 한 장씩 보냅니다.

## 5. 문제가 생기면

| 증상 | 확인 |
|---|---|
| `... is not a prepared folder` | 파이프라인의 prepare 단계가 끝나야 합니다. 설정 파일 경로(`CONFIG`)가 맞는지 확인합니다. |
| 모델 목록이 비어 있음 | 파이프라인 평가 단계가 끝나야 `runs/bank1/reports/`에 답이 생깁니다. 리허설 결과는 `SMOKE=1`로 봅니다. |
| 직접 테스트 버튼이 꺼져 있음 | 모델 폴더를 주고 띄워야 합니다: `bash viewer/bank_start.sh <모델 폴더> <GPU>` |
| `Model server exited` | `viewer/bank-model-server.log` 마지막 줄을 봅니다. GPU가 학습·평가에 쓰이고 있으면 뜨지 않습니다. |
| `docgen code not found` | 채점기가 든 docgen 코드를 찾지 못했습니다. 설정의 `data.docgen_root`(`docgen/`이 들어 있는 폴더)를 확인합니다. |
