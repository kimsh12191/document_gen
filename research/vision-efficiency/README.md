# 연구: 빈 곳은 안 본다

> **가설:** 서류 페이지의 빈 곳(흰 여백) 토큰은 빼도 성능이 그대로이고, 그만큼 빨라진다.

브랜치 `claude/vision-token-efficiency`

## 아이디어

- 페이지 한 장 ≈ 3,600 비전 토큰(토큰 하나 = 32×32px). 서류는 상당 부분이 흰 여백입니다.
- **거의 흰색인 토큰은 모델에 넣지 않습니다.** 남은 토큰은 원래 위치 번호를 그대로 씁니다(좌표가 어긋나지 않게).
- 질문과 무관하게 이미지만 보고 정하므로, 한 페이지에 질문이 많아도 프리픽스 캐시는 그대로 살고, 여러 페이지 질문은 페이지 수만큼 이득이 커집니다.

비슷한 시도로 [PixelPrune](https://github.com/OPPO-Mente-Lab/PixelPrune)(같은 픽셀 패치를 인코더 앞에서 제거, 학습 없음, Qwen3.5 지원 코드 공개)과 [Index-Preserving Token Pruning](https://github.com/sujin-1013/index-preserving-lightweight-token-pruning)(배경 패치 제거, 위치 번호 유지)이 있습니다. 구현은 PixelPrune 코드에서 출발합니다.

## 실험 1: 빼도 그대로인가 (학습 없음)

| 항목 | 내용 |
|---|---|
| 모델 | 지금 1부 SFT 모델 |
| 데이터 | 내부 OCR benchmark (1부), 생성 은행 업무 benchmark (2부) |
| 조건 | 안 뺌(기준) / 흰 토큰 빼기 (기준값 2~3개) |
| 측정 | 과제별 성능, 남은 토큰 비율, 문항당 지연 · 처리량 |
| 성공 | **토큰 30% 이상 감소, 성능 하락 1%p 이내** |

## 그다음

1. 성능이 떨어지면: 뺀 입력으로 학습시켜 회복되는지 본다.
2. 성능이 그대로면: 아낀 토큰으로 해상도를 올려, 같은 토큰 수에서 작은 글자 · 좌표가 좋아지는지 본다. (원래 문제: 잘 안 보임)

## 실행 환경

실제 숫자는 내부망(서류 이미지, SFT 모델, vLLM)에서 냅니다. 이 저장소의 합성 예시 데이터로는 코드가 돌아가는지만 확인합니다.
