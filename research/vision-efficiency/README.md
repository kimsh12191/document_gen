# 연구: 적은 비전 토큰으로 정확히 읽는 문서 VLM

> **한 줄:** 은행 서류 VLM의 글자·좌표 오류는 대부분 "픽셀이 모델까지 안 가는 것"과 "인코더가 작은 글자를 구분 못 하는 것"에서 나온다. 해상도를 무작정 올리면 느려지므로, **같은 정확도를 가장 적은 비전 토큰(= 추론 시간)으로 얻는 방법**을 찾는다.

브랜치 `claude/vision-token-efficiency` (출발점: `claude/ocr-banking-benchmark`의 1부 OCR 학습 코드와 데이터)

## 1. 배경

### 문제

1부 OCR 학습 후에도 남는 오류는 좌표 밀림과 글자 오독(비슷한 글자, 작은 숫자)입니다. 원인을 둘로 봅니다.

| 원인 | 뜻 | 확인 방법 |
|---|---|---|
| ① 픽셀 부족 | 글자가 모델 입력에서 너무 작아 정보가 없음 | 같은 단어를 잘라서 크게 주면 맞힘 |
| ② 인코더 한계 | 픽셀은 충분한데 비슷한 글자를 구분 못 함 | 잘라서 크게 줘도 틀림 |

### 현재 설정 (출발점)

| 항목 | 값 | 위치 |
|---|---|---|
| 모델 | Qwen3.5-9B (`model_type: qwen3_5`) | `training/configs/sft.yaml` |
| 이미지 크기 | 긴 변 2300 · 짧은 변 1600 이하로 축소 | `image_max_size`, `training/bank_ocr/pipeline.py` |
| 비전 토큰 | 토큰 하나 ≈ 32×32px, 페이지 한 장 ≈ 3,600토큰 | `training/train.py` (`IMAGE_MAX_TOKEN_NUM`) |
| 인코더 학습 | LoRA rank 32 (`all-linear`, `freeze_vit: false`), 인코더 전용 lr 없음 (`vit_lr` 주석) | `training/configs/sft.yaml` |
| 서빙 | ms-swift + vLLM, `IMAGE_MAX_TOKEN_NUM`으로 해상도 고정 | `training/run_pipeline.py` |
| 평가 | 예측과 점수만 기록, **지연 시간은 기록 안 함** | `training/bank_ocr/inference.py` |

어림셈: A4를 긴 변 2300px로 줄이면 1mm ≈ 7.7px입니다. 10pt 한글(약 3.5mm)은 약 27px, 8pt는 약 22px로 **글자 하나가 토큰 한 칸(32px)보다 작습니다.** 여러 장을 넣는 은행 업무 문항은 장마다 더 줄어듭니다.

### 왜 속도가 같이 문제인가

- 비전 토큰 수가 인코더 시간, 언어 모델 prefill, KV 메모리를 함께 늘립니다. 인코더는 전역 어텐션 층 때문에 토큰 수보다 빠르게 늘어납니다.
- 따라서 "해상도 2배"는 정확도에는 좋지만 비용은 4배 이상이 됩니다.
- 반면 **인코더를 더 학습시키는 것은 구조가 같으면 추론 비용이 0**입니다.

## 2. 연구 질문과 지표

**연구 질문:** 목표 정확도를 내는 데 필요한 비전 토큰을 얼마나 줄일 수 있나? 줄이는 세 가지 수단(픽셀 배분, 인코더 학습, 토큰 제거)은 각각 얼마나 기여하고, 함께 쓰면 어떻게 되나?

**모든 실험은 같은 그래프 위의 점이나 곡선으로 비교합니다.**

| 축 | 지표 |
|---|---|
| y: 정확도 | 글자: CER, 완전 일치율 (crop_ocr · bbox_ocr · region_ocr · spotting) / 좌표: IoU≥0.5 F1, 평균 IoU (grounding · spotting · marked_box) / 업무: 은행 업무 벤치마크 점수 (2부, 회귀 확인용) |
| x: 비용 | 페이지당 비전 토큰 수, 페이지당 지연(인코더 / prefill / 디코딩 분리), 같은 GPU에서의 처리량(페이지/초) |

**대표 지표: 필요 토큰 T\*.** 기준 모델을 원본 크기(2300×1600, 약 3,600토큰)로 돌렸을 때의 정확도에서 1%p 이내를 내는 최소 비전 토큰 수입니다. 세 트랙의 성과를 모두 "T\*를 몇 % 줄였나"로 말합니다.

**측정 조건 고정:** GPU 종류, vLLM·ms-swift 버전, 동시 요청 수, `max_tokens`, 같은 benchmark 문항(`benchmark_tasks.jsonl`)을 실험 기록마다 함께 저장합니다.

## 3. 0단계: 공통 기준선 (모든 트랙의 전제)

세 트랙을 비교하려면 기준 곡선이 먼저 있어야 합니다. 학습 없이 추론만 합니다.

- **해상도 스윕:** 기준 모델과 1부 SFT 모델을 긴 변 2300 / 1900 / 1600 / 1300 / 1000 / 800에서 추론합니다. 각 크기에서 정확도, 토큰 수, 지연을 기록합니다.
- **글자 높이 곡선:** OCR 박스 높이(`pages.jsonl`)를 축소 비율로 환산해, 글자 높이 구간(px)별 정확도를 그립니다. 정확도가 무너지는 글자 높이 h\*를 구합니다.
- **잘라 준 경우와 비교:** 같은 단어에 대해 페이지 전체에서 읽기(region_ocr · spotting)와 잘라서 읽기(crop_ocr)를 비교합니다. 원인 ①과 ②의 비중을 알 수 있습니다.
- **산출물:** 기준 곡선(정확도-토큰, 정확도-글자 높이), h\*, 기준 T\*, 지연 분해 표.

## 4. 트랙 A: 픽셀을 글자 있는 곳에만 쓰기 (H2)

**가설.** 서식 문서는 대부분 여백이다. 저해상도 전체 이미지 1장에 글자 영역만 h\* 이상이 되도록 잘라 붙이면, 전체 고해상도와 같은 정확도를 훨씬 적은 토큰으로 얻는다.

**방법**
- **입력 구성:** 전체 이미지(예: 긴 변 800, 약 400토큰)와 글자 영역 조각 K개를 함께 넣습니다. 조각마다 축소 비율은 그 영역의 글자가 h\*가 되도록 정합니다.
- **글자 영역 고르기:** 사내 OCR 박스를 줄·블록 단위로 묶습니다. 실서비스에서 OCR을 이미 돌린다면 추가 비용이 없습니다. OCR이 없는 경우의 대안(모델이 직접 1차로 영역 고르기)은 두 번째 단계로 둡니다.
- **좌표:** 모델은 페이지 전체 기준 좌표로 답하게 합니다. 조각마다 페이지에서의 위치를 프롬프트에 적고, 학습 데이터의 정답은 원래 페이지 좌표 그대로 둡니다.
- **학습:** prepare에 입력 구성 옵션을 추가해 같은 문항을 새 입력 형식으로 만들고 SFT를 다시 합니다. `crops/`·`tiles/` 생성 코드를 재사용합니다.

**비교군**
- 같은 토큰 수로 전체를 균일하게 축소한 것(0단계 곡선)
- 두 번 묻기(1차 저해상도로 영역 고르기 → 2차 확대 조각 읽기, 호출 2회)

**성공 기준:** 같은 정확도에서 T\* 40% 이상 감소, 또는 같은 토큰에서 좌표 F1 · CER 개선.

**위험**
- 조각 경계에서 글자가 잘림 → 조각마다 여백을 둡니다.
- 조각이 많으면 오히려 토큰이 늘어남 → 조각 수와 토큰 상한을 실험 변수로 둡니다.
- spotting처럼 페이지 전체를 다루는 과제에서 빠지는 글자 → 영역을 고를 때 재현율을 따로 측정합니다.

## 5. 트랙 B: 인코더를 학습시켜 필요한 픽셀 줄이기 (H3)

**가설.** 지금은 인코더를 LoRA rank 32로만 학습해서 작은 글자와 비슷한 글자를 구분하는 능력이 부족하다. 인코더를 전체 학습하고 작은 글자 위주 데이터를 넣으면, 글자 높이 곡선이 왼쪽으로 이동해 h\*와 T\*가 줄어든다. 추론 비용은 그대로다.

**방법**
- **학습 설정 비교** (같은 데이터, 같은 스텝)
  - (a) 현재: 전체 LoRA r32
  - (b) 인코더 전체 학습(`vit_lr` 2e-5 근처) + 언어 모델 LoRA
  - (c) (b) + merger(aligner) 전체 학습
  - (d) (b)를 낮은 해상도 입력으로 학습: 목표 해상도에서 읽는 법을 직접 학습
- **데이터**
  - 실제 OCR 데이터를 여러 축소 비율로 만든 사본
  - docgen 합성 글자 데이터: 작은 글씨(6~9pt 상당), 비슷한 글자쌍(0/O, 1/l/I, 비슷한 한글 음절), 팩스 · 흐림 · 기울어짐 · 도장 겹침
  - 무작위 문자열(언어 모델이 그럴듯한 단어로 고쳐 읽는 것 방지)
- **측정:** 0단계와 같은 해상도 스윕을 다시 돌려 곡선이 얼마나 이동했는지 봅니다(h\*, T\*). 비슷한 글자쌍 CER도 따로 봅니다.

**성공 기준:** 같은 해상도에서 CER이 의미 있게 감소, 또는 h\* 감소. 이 결과로 트랙 A의 조각을 더 작게 만들 수 있습니다.

**위험**
- 인코더 전체 학습으로 일반 시각 능력(체크박스, 도장, 배치) 저하 → 2부 은행 업무 벤치마크로 회귀를 확인합니다.
- 메모리 증가 → A100 40GB×2 설정에서 가능한지 먼저 확인합니다.

## 6. 트랙 C: 쓸모없는 토큰 버리기 (H4)

**가설.** 흰 배경 패치의 비전 토큰은 정보가 거의 없다. 언어 모델에 넣기 전에 빼도 정확도는 거의 그대로이고, prefill과 KV는 그만큼 줄어든다.

**방법**
1. **세기:** 모델 없이 32×32 패치의 픽셀 분산으로 배경 토큰 비율을 셉니다(서류 종류별). 이 비율이 절약할 수 있는 최대치입니다.
2. **학습 없이 빼 보기:** merger 출력 뒤, 언어 모델 입력 전에 배경 토큰을 제거합니다. 위치 정보(M-RoPE 위치 id)는 원래 값을 유지해 배치가 깨지지 않게 합니다. HF transformers로 정확도부터 확인합니다.
3. **짧은 적응 학습:** 정확도가 떨어지면 뺀 상태로 SFT를 조금 합니다.
4. **서빙:** vLLM에서 같은 동작을 할 수 있는지 확인하고, prefill 시간 절약을 실측합니다. 인코더 시간은 이 방법으로 줄지 않습니다(인코더 앞에서 빼는 것은 별도 실험).

**성공 기준:** 비전 토큰 30% 이상 제거 시 정확도 하락 1%p 이내, prefill 지연 감소 실측.

**위험:** 모델 구조와 서빙 코드를 건드려야 해서 세 트랙 중 가장 위험합니다. 트랙 A가 입력 단계에서 같은 효과를 상당 부분 내므로, A의 결과를 보고 범위를 정합니다.

## 7. 세 트랙의 관계

- **B는 A를 강하게 합니다.** h\*가 낮아지면 A의 조각을 더 작게 잘라도 됩니다.
- **C는 A가 남긴 여백을 줄입니다.** A의 저해상도 전체 이미지와 조각 안의 여백에 적용합니다.
- **최종 실험:** 0단계 기준 → A → A+B → A+B+C 순서로 T\*와 지연이 얼마나 줄었는지를 하나의 표로 냅니다.

## 8. 순서와 결정 지점

| 단계 | 내용 | 학습 | 결정 |
|---|---|---|---|
| 0 | 기준 곡선, h\*, 지연 측정 도구 | 없음 | 원인 ①·②의 비중 → A·B 우선순위 |
| 1 | 트랙 C-1 배경 토큰 세기 | 없음 | 절약 여지가 작으면 C 중단 |
| 2 | 트랙 A 입력 구성 + SFT | 있음 | T\* 감소 확인 |
| 3 | 트랙 B 학습 설정 (a)~(d) | 있음 | 곡선 이동 확인, 회귀 확인 |
| 4 | 트랙 C-2~4 | 구조 변경 | A 결과를 보고 범위 결정 |
| 5 | 조합 (A+B+C) | 있음 | 최종 표 |

## 9. 폴더 구조 (예정)

```
research/vision-efficiency/
  README.md          이 문서
  NOTES.md           실험 기록 (날짜, 설정, 결과, 결론)
  measure/           0단계: 해상도 스윕, 글자 높이 곡선, 지연 측정
  track_a_crops/     트랙 A: 입력 구성 (prepare 옵션), 비교 실험
  track_b_encoder/   트랙 B: 학습 설정, 합성 글자 데이터
  track_c_prune/     트랙 C: 배경 토큰 세기, 토큰 제거 모델
```

`training/`은 OCR 브랜치(`claude/bank-ocr-pipeline`)와 같은 코드라 직접 고치지 않습니다. 연구 코드는 이 폴더에서 `training/bank_ocr`를 가져다 씁니다. 연구 결과로 학습 코드 변경이 필요해지면, 그때 OCR 브랜치에 반영합니다.

## 10. 데이터와 실행 환경

- 실제 학습·평가는 내부망의 서류 이미지와 사내 OCR 결과로 합니다(1부와 같은 manifest · prepared 폴더).
- 이 저장소의 합성 예시 데이터(`guide/examples/make_examples.sh`)로 코드가 돌아가는지만 먼저 확인합니다.
- 실험 기록에 남기는 숫자는 내부망 실측 값만 씁니다.
