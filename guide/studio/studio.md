# studio 사용법

studio 는 **서식을 보고·고치고·검수**하고, **새 서식을 그려 더하고**, **데이터셋을 만드는** 웹 화면입니다.
학습·평가는 studio 가 아니라 GPU 학습 서버에서 합니다.

```text
  서식 (보기·고치기·검수) ──┐
                            ├──▶  데이터셋 (레시피로 만들기 → 문항 확인)  ──▶  학습 서버
  새 서식 추가 (칸 그리기) ─┘
```

처음 보는 말은 맨 아래 [말 뜻](#말-뜻).

## 접속

받은 주소로 들어갑니다. 내부망 서버에 떠 있으면 내 PC 에서 터널을 열고 브라우저로 `http://localhost:8765`:

```bash
ssh -N -L 8765:localhost:8765 <계정>@<서버IP>     # 이 창은 열어 둠
```

로그인이 없으니 주소를 아무에게나 열지 않습니다. 직접 띄우는 법은 `studio/README.md`.

## 메뉴

| 메뉴 | 하는 일 |
|---|---|
| **서식** | 서식 목록 → 서식 하나를 열어 보고, 고치고, 검수 |
| **새 서식 추가** | 서식 그림을 올리고 그 위에 칸을 그려 새 서식을 만듦 |
| **데이터셋** | 레시피로 평가 세트·학습 데이터를 만들고 문항을 봄 |
| 표시 요소 | 모든 서식 공통: 체크·도장·서명이 나올 확률, 아무 데나 찍히는 접수인·번호 |
| OCR 예시 | OCR 과제가 어떤 질문·정답인지 예시 |
| 사용 가이드 | 이 문서들. 왼쪽 아래 **? 이 화면 도움말** 은 지금 화면의 절로 바로 감 |

## 할 일별로

### 1. 서식 하나가 어떻게 나오는지 보기

1. **서식** 목록에서 검색(ID·이름)해 엽니다.
2. **개요**: 이 서식이 묻는 것 — 칸·표·체크·도장 목록과 분류 정답(문서명).
3. **생성 사례 › 미리보기**: 가짜 고객(seed)으로 그린 그림 + 칸마다 정답 상자. ◀ ▶ 로 seed 를 바꿔 봅니다. **키 이름** 을 켜면 상자마다 키가 보입니다.
4. **질문·답**: **[실제 문항 예시 만들기]** → 과제마다 모델이 받는 질문과 정답. 그림을 누르면 큰 창에서 상자마다 키·값, 질문·답이 보이고 위 고르기로 다른 과제(표·도장 …) 문항으로 넘어갑니다.

### 2. 서식 검수하기

1. **생성 사례 › 미리보기**에서 seed 를 몇 개 넘기며 원본과 견줘 봅니다. 이상한 곳은 **[문제 표시]** 를 켜고 그림을 눌러 메모를 남깁니다.
2. **생성 사례 › 검수**: 자동 검사 경고(한글 키, 같은 키를 여러 칸, 지우지 않은 실서류 값 …)와 남은 문제를 봅니다.
3. 괜찮으면 **[검수 완료]**. 학습/평가 **배정**도 여기서 정합니다 (평가 전용이면 학습 데이터에서 빠짐).

- 검수 완료는 **사람이 눈으로 본 것**입니다. 자동 검사 통과와 다릅니다.
- 검수한 뒤 서식이 바뀌면 "재검수 필요"로 돌아갑니다.

### 3. 값·위치가 이상할 때 고치기

서식 종류에 따라 고치는 곳이 다릅니다 (서식 위쪽 태그: `overlay` / `html`).

| | 그림 서식 (`overlay`: `hf###`, `img_*`) | html 서식 (`html`) |
|---|---|---|
| 어디서 | **고치기 › 영역 편집** (화면) | 파일 (코드). 화면은 **고치기 › 영역·키 보기** 로 어느 자리에 어떤 키가 나오는지만 봄 |
| 값이 이상함 | 칸을 누르고 오른쪽 **생성 방법 [고르기…]** · 날짜·금액 꼴은 **표기** | `fields.json` 의 `source`, 칸끼리 관계는 `generate.py` |
| 위치가 어긋남 | 칸을 끌어 옮김, 모서리로 크기 | `look/template.html.j2` |
| 칸 더하기·빼기 | 위 도구로 그리기 · `Delete` | 템플릿의 `f("키")` + `fields.json` |
| 분류 정답(문서명) | **개요**의 문서 분류 줄 **[바꾸기]** | 같음 |

- 영역 편집은 **[저장]** 을 눌러야 파일에 들어갑니다. 아래 **수정 전후 비교**로 저장본과 견줍니다.
- 고르기 창에 원하는 값이 없으면 → [원하는 값이 고르기 창에 없을 때](generators.md).
- html 서식을 파일로 고치거나 LLM 에게 맡기는 법은 저장소 `docgen/forms/README.md` 0절 (무엇을 어느 파일에서).
- 고친 뒤에는 미리보기로 확인하고 다시 **검수 완료**.

### 4. 새 서식 추가하기

**그림 위에 칸을 그리는 서식** — 화면에서 합니다.

1. **새 서식 추가**: 그림(PNG·JPG·PDF), 서식 ID(`img_…`), 서식 이름(= 분류 정답) → **[만들고 영역 편집으로]**.
2. 값 자리마다 칸을 그리고 칸마다 **키 · 키 설명 · 생성 방법**.
3. **[저장]** → 미리보기·질문·답으로 확인 → **검수 완료**. 검수 완료된 서식만 레시피의 `"all"` 에 들어갑니다.

도구·표·날짜 칸·자유 위치 도장 등은 [새 서식 추가](new-forms.md), 키 이름은 [키 이름 정하기](keys.md).

**html 서식으로 만들기** — 화면이 없습니다. 저장소의 `docgen/manual/NEW_FORM_SPEC.md` 를 서식 그림과 함께 LLM(클로드 코드 등)에게 주고 `docgen/forms/<새 ID>/` 폴더를 만들게 합니다 (원본 그림이 실서류면 사내 모델에만).
폴더가 생기면 서식 목록의 **[서식 다시 읽기]** → 미리보기·검수는 위와 같습니다.

### 5. 데이터셋 만들고 확인하기

1. **데이터셋 › 새로 만들기**: 레시피를 고르고 이름을 정해 **[만들기]**.

   | 레시피 | 만드는 것 |
   |---|---|
   | `bank-bench` · `bank-train` | 서류 평가 세트 (서식마다 1건) · 학습 데이터 (서식마다 5건) |
   | `ocr-bench` · `ocr-train` | 쪽 전체 글자 OCR 평가 세트 · 학습 데이터 |
   | `bank-try` | 몇 분짜리 시험 |

2. **생성 현황**에서 진행을 봅니다. 끝나면 **등록된 데이터셋**에 저절로 들어갑니다.
3. 데이터셋을 열어 **문항** 탭에서 그림·질문·정답을 몇 개 눈으로 봅니다. **구성** 탭은 과제별 문항 수, **설명서** 탭은 목적·한계 메모.
4. 평가 세트는 한 번 정하면 **[고정]** 하고 계속 씁니다.

- **처음에는 작게** 만들어 보고 크게 만듭니다.
- 레시피 이름을 누르면 서식·수량·촬영 조건을 고칩니다. 기본 레시피를 고치면 저장소 파일이 바뀌므로, 다른 설정은 **틀에서 새 레시피**로 따로 만듭니다.
- 레시피 칸, 화면 없이 명령으로 만들기는 [데이터셋 만들기](data.md). 만든 데이터셋으로 학습·평가하는 법은 학습 서버 쪽 문서(저장소 `guide/train/sweep.md`).

### 6. 모든 서식에 공통인 표시 바꾸기

**표시 요소**: 체크박스가 체크될 확률, 도장·서명이 찍힐 확률, 손글씨 비율, 모든 서식에 아무 데나 찍히는 접수인·번호.
서식 하나에만 넣으려면 그 서식의 영역 편집 › **자유 위치 (도장·글자)** 도구.

## 서식 화면 탭 한눈에

| 탭 | 화면 | 하는 일 |
|---|---|---|
| 개요 | 요약 · 카드 원문 | 묻는 것(칸·표·체크·분류 정답), 상태, 분류 정답 바꾸기 |
| 생성 사례 | 미리보기 · 여러 장 보기 · 검수 | 그려 본 그림과 정답 상자, 검수 완료·배정 |
| 질문·답 | 실제 문항 | 과제마다 질문·정답. 그림을 누르면 큰 창 |
| 고치기 | 그림 서식: 영역 편집 · 파일 / html 서식: 영역·키 보기 · 파일 | 고치기 (html 은 보기만, 고치는 건 파일로) |

## 막힐 때

| 증상 | 할 일 |
|---|---|
| 칸 목록 **생성** 열에 빨간 "자동 → 빈 칸" | 그 칸의 생성 방법을 고릅니다 |
| 검수 경고: 한글 키 · 같은 키를 여러 칸 | 키를 영어로, 칸마다 다르게 ([keys.md](keys.md)) |
| 검수 경고: 지우지 않은 실서류 값 | 영역 편집의 **지우기**로 덮습니다 |
| 새로 만든 서식이 데이터셋에 안 나옴 | 검수 완료를 안 했거나, 레시피의 빼는 서식에 들어 있음 |
| 미리보기가 안 그려짐 | 왼쪽 아래 안내: 렌더링 브라우저가 없음 (설정) |
| 사내 OCR 로 읽기 버튼이 꺼져 있음 | studio 설정에 사내 OCR 이 없음 (내부망에서만) |

## 말 뜻

| 말 | 뜻 |
|---|---|
| **서식** | 서류 한 종류 (재직증명서, 대출거래신청서 …). 폴더 `docgen/forms/<ID>/` 하나 |
| **그림 서식** (`overlay`) | 원본 그림 위에 값을 찍는 서식. `hf###` 하나은행 원본, `img_*` 새로 그린 것. 화면(영역 편집)에서 고침 |
| **html 서식** (`html`) | 모양을 html 템플릿으로 그리는 서식. 파일로 고침 |
| **칸** | 값이 들어가는 곳 하나 (글자 칸, 체크 보기, 서명·도장 자리, 표의 한 칸) |
| **키** | 정답에서 칸을 가리키는 영어 이름 (`customer.name`). 서식마다 따로 정함 |
| **키 설명** | 칸이 무엇인지 적은 말. 보통 서식에 인쇄된 칸 이름 (`성명`). 질문에 `- 키: 키 설명` 으로 나감 |
| **생성 방법** | 문서를 만들 때마다 칸에 넣을 값의 규칙 (고객 이름, 날짜, 보기 중 하나 …) |
| **표기** | 날짜·금액을 찍는 꼴 (`250131`, `1,234,000원`) |
| **seed** | 가짜 고객과 무작위 선택을 정하는 번호. 같은 seed → 같은 그림 |
| **문항** | 그림 + 질문 + 정답 한 개 |
| **과제** | 문항의 종류: 분류, 값 추출(kie), 체크·도장·서명, 표 4종, 기타 칸 정리, 서식 전용 질문, 글자 읽기(OCR) |
| **레시피** | 데이터셋을 만드는 설정 (어떤 서식, 몇 건, 촬영 조건) |
| **검수 완료** | 사람이 그림·정답을 눈으로 보고 표시한 것. 자동 검사 통과와 다름 |
