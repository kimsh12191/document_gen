meta 키 (1/3)

키뜻
scenario업무 ID (예: `jeonse_loan`)
task_name업무 이름 (질문에 들어가는 이름)
bundle고객 묶음 ID `<업무>_<seed>`
customer고객 성명 (질문에 들어감)
n_missing필수 서류 중 뺀 개수 (0~2, 다른 고객 서류로 바꾼 것은 세지 않음)
not_customer다른 고객 서류를 섞었는지
not_required업무와 상관없는 서류를 끼워 넣었는지
n_docs질문에 보여 준 서류 수
case불일치 사례 ID
category사례 분류: typo 오기 / other_person 타인 / amount 금액 / logic 관계 / format 표기만 다름
perturbed값을 바꾼 변조 문항인지 (false = 같은 서류 조합의 정상 문항)
