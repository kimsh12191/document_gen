# 질문·답변 가이드 (은행 업무 과제)

은행 업무 단계에서 학습한 모델에게 **어떻게 물으면 어떤 형식으로 답하는지** 정리한 문서입니다. 모델은 아래 질문 문장으로 학습했으므로 같은 문장으로 물을 때 가장 정확합니다. 문장을 바꾸면 답 형식이 흐트러질 수 있습니다.

- 질문 문장은 `docgen/bench/prompts.py`와 같습니다(평가 세트, 학습 데이터, studio가 모두 이 파일을 씁니다). 테스트(`docgen/tests/test_bench.py`)가 이 문서와 코드가 같은지 확인합니다.
- OCR 과제(박스 찾기, 영역 읽기 등)의 질문은 [tasks.md](tasks.md#ocr-과제)에 있습니다(원본 `docgen/bench/ocr_tasks.py`의 `PROMPTS`). OCR 데이터를 섞어 함께 학습하므로 그 질문도 됩니다.
- `{customer}`처럼 중괄호로 쓴 곳은 실제 값으로 바꿔 넣는 자리입니다.

## 질문에 넣을 목록은 어디서 찾나

질문 문장 외에, 질문에 채워 넣는 **목록**은 생성기 문서에 자동 생성되어 있습니다. 학습 때 모델이 본 이름·키가 이 목록 그대로입니다.

| 목록 | 쓰는 과제 | 위치 |
|---|---|---|
| 서류별 항목 키·항목명·타입 (476종) | `kie`의 `{items}` | [fields/](fields/README.md) (그룹별 파일), 기계용 [fields/fields.json](fields/fields.json) |
| 체크박스 보기, 도장·서명 자리 | `marks`의 `{items}` | 같은 [fields/](fields/README.md) (타입 `checkbox`는 예시 칸에 보기 전체, `seal`·`signature`는 `seal.<자리>`·`sign.<자리>`) |
| 서류 정식 명칭 (476종) | `classify`의 답, `doc_check`·`cross_check`·`review`의 서류명 | [documents.md](documents.md) |
| 업무 12종과 업무별 필수 서류 | `doc_check`의 `{task}`·`{required}`, 나머지 과제의 `{task}` | [documents.md#업무-시나리오](documents.md#업무-시나리오) |

- **표의 행:** 항목 목록에는 `rows[].amount`처럼 적혀 있습니다. 질문할 때는 `rows.0.amount`, `rows.1.amount`처럼 번호를 넣습니다.
- **목록을 다시 만들 때:** 생성기 코드가 바뀌면 다시 만듭니다.
  - `python docgen/scripts/build_schema.py`: `fields/`
  - `python -m docgen list --markdown > guide/documents.md`: `documents.md`
- **실제 서류:** 학습 목록에 없는 서류는 키를 직접 정해 물어도 됩니다. 다만 학습한 키와 이름을 쓸수록 정확합니다.

## 공통 규칙

| 항목 | 규칙 |
|---|---|
| 이미지 순서 | 이미지를 모두 먼저 넣고 질문 글을 마지막에 넣습니다. 여러 서류면 서류 순서대로, 한 서류의 쪽은 1쪽부터 |
| 이미지 크기 | 한 장은 긴 변 2300·짧은 변 1600 이하. 한 질문의 이미지 합이 약 12,000 토큰(32px 한 칸 기준) 이하가 되도록 장마다 같은 비율로 줄입니다. 예: 13장이면 장당 약 920토큰. 학습 실행의 평가(`train/mix.py`)가 이 규칙을 그대로 씁니다 |
| 이미지 수 | 한 질문에 최대 16장 (서버 `--vllm_limit_mm_per_prompt {"image": 16}`). 학습은 최대 13장까지 봤습니다 |
| 생성 설정 | `temperature 0`, `enable_thinking false`, `max_tokens 4096` (`train/configs/inference.json`) |
| JSON 답 | 한 줄 JSON으로 답합니다. ```` ```json ```` 코드 블록으로 감싸 올 수 있으니 받는 쪽에서 벗겨 냅니다 |
| 서류명 | 학습한 서류명은 docgen 서류 목록의 정식 명칭입니다([documents.md](documents.md)). 실제 서류에 다른 이름을 쓰면 그 이름을 질문에 그대로 적으세요 |

## 한눈에 보기

| 과제 | 넣는 이미지 | 질문에 채울 것 | 답 |
|---|---|---|---|
| `doc_check` 서류 구비 확인 | 제출 서류마다 **첫 쪽만** | 고객 성명, 업무명, 필수 서류 목록 | `{"missing": [], "not_required": [], "not_customer": []}` |
| `cross_check` 서류 대조 | 대조할 서류 2~3건의 **모든 쪽** | 고객 성명, 업무명, 서류 수, 이미지 수 | `{"consistent": true/false, "issues": [...]}` |
| `review` 심사 질의 | 질문에 필요한 서류 1~2건의 모든 쪽 | 업무명, 이미지 수, 질문 | 숫자 하나 또는 `예`/`아니오` |
| `kie` 정보 추출 | 서류 한 건의 모든 쪽 | 뽑을 항목 (`키: 항목명`) | `[{"key", "value", "bbox_2d", "page"}, ...]` |
| `marks` 체크·도장·서명 | 서류 한 건의 모든 쪽 | 항목과 보기 | `[{"key", "value": 보기·true/false, "bbox_2d", "page"}, ...]` |
| `freetext` 기타 칸 정리 | 서류 한 건의 모든 쪽 | 칸 이름, 기준일 | `{"purpose": …, "amount": 정수, …}` (적힌 키만) |
| `classify` 서류 분류 | 서류 한 건의 모든 쪽 | 없음 | 서류명 한 줄 |
| `ocr_page` 전체 받아쓰기 | 서류 한 건의 모든 쪽 | 없음 | 읽은 글자 (줄바꿈) |
| `ocr_field` 값 칸 읽기 | 값 칸 하나를 잘라낸 이미지 | 없음 | 적힌 글자 |

## doc_check — 서류 구비 확인

**질문**
```
고객 '{customer}' 님이 '{task}' 업무를 위해 서류를 제출했습니다. 첨부 이미지는 제출된 서류의 첫 쪽입니다 (순서 무관).
필수 제출 서류:
{required}

제출 서류를 확인해 다음을 JSON 으로 답하세요.
- missing: 필수 서류 중 제출되지 않은 서류. 고객 본인 명의가 아닌 서류만 낸 경우도 제출되지 않은 것으로 봅니다.
- not_required: 제출됐지만 필수 서류 목록에 없는 서류
- not_customer: 고객 본인 명의가 아닌 서류
{"missing": ["서류명", ...], "not_required": [...], "not_customer": [...]} 형식으로 답하고, 해당 없으면 빈 목록 [] 으로 두세요. 서류명은 목록에 있으면 목록 그대로, 없으면 서류에 적힌 제목대로 쓰세요.
```
- `{required}`는 한 줄에 하나씩 번호를 붙입니다: `1. 주민등록증\n2. 재직증명서\n…`
- 이미지는 제출 서류마다 첫 쪽 한 장이고 순서는 상관없습니다.

**답 예**
```json
{"missing": ["재직증명서", "주민등록증"], "not_required": ["납세증명서(법인)"], "not_customer": ["주민등록증"]}
```
- 다른 사람의 주민등록증만 냈으면 `not_customer`와 `missing`에 모두 들어갑니다.
- `missing`·`not_customer`는 필수 서류 목록의 이름 그대로, `not_required`는 서류에 적힌 제목대로 씁니다.

**학습한 범위:** 업무 12종의 필수 서류 목록(5~12건), 빠진 서류 0~2건, 다른 고객 서류 0~1건, 상관없는 서류 0~1건. 업무별 필수 서류는 [benchmark.md](benchmark.md)와 docgen 시나리오 정의에 있습니다.

## cross_check — 서류 대조

**질문**
```
고객 '{customer}' 님이 '{task}' 업무를 위해 제출한 서류 {n}건입니다 (이미지 {pages}장). 서류들을 서로 대조해 맞지 않는 정보(성명, 주민등록번호, 생년월일, 주소, 연락처, 계좌번호, 상호, 금액, 날짜 등), 업무상 맞지 않는 관계(계약 상대방이 등기부 소유자가 아님, 금액·날짜 관계 오류 등), 고객 본인 명의가 아닌 서류가 있는지 확인하세요. 표기 방식만 다른 것(날짜 형식, 주민번호 뒷자리 가림, 하이픈 유무 등)은 불일치가 아닙니다.
{"consistent": true 또는 false, "issues": [{"document": "문제가 있는 서류명", "field": "항목명", "value": "그 서류에 적힌 값", "expected": "다른 서류에 적힌 값"}]} 형식의 JSON 으로 답하세요. 문제가 없으면 {"consistent": true, "issues": []} 입니다.
```

**답 예**
```json
{"consistent": false, "issues": [{"document": "주택임대차표준계약서", "field": "임대인", "value": "신수유", "expected": "추규태"}]}
{"consistent": true, "issues": []}
```
- `value`는 문제 서류에 적힌 값, `expected`는 다른 서류에 적힌(맞아야 하는) 값입니다.

**학습한 범위**
- **서류 수:** 한 질문에 서류 2~3건, 이미지 10장 이하입니다.
- **불일치:** 학습에서는 한 질문에 불일치가 **최대 1개**였습니다. 그래서 `issues`도 보통 하나만 답합니다. 실제 서류에 불일치가 여럿일 수 있으면 서류 쌍을 나눠 여러 번 물으세요.
- **사례:** 오기, 타인 서류, 금액(신청↔약정, 소득 부풀리기), 관계(임대인·매도인≠소유자, 입사일≠건보 취득일, 법인 대표자, 약정일<신청일, 채권최고액 부족, 전세대출>보증금, 업계약, 송금 수취인≠송장 수출자), 표기만 다른 정상 문항. 자세한 내용은 [benchmark.md](benchmark.md#불일치-사례)에 있습니다.

## review — 심사 질의

**질문**
```
고객이 '{task}' 업무를 위해 제출한 서류입니다 (이미지 {pages}장).
{question}
```
`{question}`은 아래 학습 패턴을 따르면 가장 정확합니다. 공통 패턴은 이렇습니다.
- 서류를 **작은따옴표 안의 서류명**으로 가리킵니다.
- **답 형식을 괄호로 끝에** 적습니다.

| 유형 | 질문 패턴 (학습 문장 그대로) | 답 |
|---|---|---|
| 같은지 대조 | `'{서류A}'의 {항목}이 '{서류B}'의 {항목}과 같습니까? ('예' 또는 '아니오'로만 답하세요)` | `예` / `아니오` |
| 관계 대조 | `'{서류A}'의 임대인이 '{서류B}'의 현재 소유자와 같은 사람입니까? ('예' 또는 '아니오'로만 답하세요)` | `아니오` |
| 크기 비교 | `'{서류A}'의 대출신청금액이 '{서류B}'의 보증금 이하입니까? ('예' 또는 '아니오'로만 답하세요)` | `예` |
| 비율 | `'{서류A}'의 대출신청금액은 '{서류B}'의 매매대금의 몇 %입니까? (LTV, 소수 첫째 자리까지 반올림한 숫자만 답하세요)` | `23.7` |
| 배수 | `'{서류A}'의 대출신청금액은 '{서류B}'의 주(현)근무지 급여 합계(계)의 몇 배입니까? (소수 둘째 자리까지 반올림한 숫자만 답하세요)` | `0.85` |
| 만 나이 | `'{신분증}'의 주민등록번호로 보아, '{신청서}'의 신청일 당일 고객의 만 나이는 몇 세입니까? (숫자만 답하세요)` | `57` |
| 재직기간 | `'{신청서}'에 적힌 입사일과 신청일로 보아, 신청일 현재 재직기간은 만 몇 년입니까? (만 1년 미만은 버리고 숫자만 답하세요)` | `4` |
| 유효기간 | `은행은 제출 서류가 업무 신청일 기준 발급 후 90일 이내여야 받습니다. '{서류}'의 발급일부터 '{신청서}'의 신청일까지 90일 이내입니까? ('예' 또는 '아니오'로만 답하세요)` | `아니오` |
| 차액 | `'{급여명세서}'의 지급액계에서 공제액계를 빼면 얼마입니까? (원 단위 숫자만 답하세요)` | `5879250` |
| 표 합계 | `'{상업송장}'의 품목별 금액(Amount)을 모두 더하면 얼마입니까? (통화 기호 없이 숫자만 답하세요)` | `56317.98` |
| 재무 비율 | `'{재무제표}'의 당기 기준 부채비율(부채총계 ÷ 자본총계 × 100)은 몇 %입니까? (소수 첫째 자리까지 반올림한 숫자만 답하세요)` | `178.6` |

- **답 꼴:** 숫자는 쉼표·단위 없이 숫자만, 예/아니오는 `예` 또는 `아니오` 한 단어입니다.
- **학습한 범위:** 계산·날짜 질문 12종(LTV, 채권최고액 비율, 전세대출 비율, 소득 대비 배수, 만 나이, 재직기간, 90일 유효기간, 급여 실수령액, 매매 잔금, 송장 합계, 학비 잔액, 부채비율)과 서류 대조 예/아니오 질문 12종(불일치 사례마다 하나)입니다. 처음 보는 계산(예: DSR)은 같은 꼴로 물어도 정확도가 확인되지 않았습니다. 기준일, 반올림 자릿수, 단위를 질문에 꼭 적으세요.

## kie — 정보 추출

**질문**
```
이 문서에서 아래 항목의 값과 위치를 찾아 JSON 목록으로 답하세요. 항목마다 {"key": 키, "value": 문서에 적힌 값 그대로, "bbox_2d": [x1, y1, x2, y2], "page": 쪽 번호} 를 쓰세요. 좌표는 그 쪽 이미지 기준 0~1000 정수, 쪽 번호는 1부터입니다. 키는 그대로 쓰고, 문서에 비어 있거나 없는 항목은 {"key": 키, "value": null} 로 답하세요.
항목 (키: 서식의 항목명 (누구의 무엇·몇 번째 행))
{items}
```
- `{items}`는 한 줄에 하나씩 `- 키: 항목명 (설명)` 꼴로 씁니다. 예: `- customer.name: 성명 (고객 성명)`, `- debts.1.balance: 잔액 (2행)`, `- date2: 작성일 (같은 항목명 중 2번째 칸)`, `- loan.amount: 대출신청금액`
- 괄호 안 설명은 키 사전(Studio 키 사전의 누구의 · 무엇, 공통 키 이름)과 키의 행 번호(0부터 → 1행부터)로 자동으로 붙입니다. 한 문서에 항목명이 같은 칸이 여럿이면(행 번호가 없는 반복 칸) 문서 순서로 몇 번째 칸인지도 붙입니다. 항목명과 같거나 정해진 것이 없으면 괄호를 뺍니다. 직접 물을 때도 같은 꼴로 쓰면 학습과 같습니다.
- 키는 질문에 쓴 그대로 답에 쓰도록 학습했습니다. 학습 키는 영어 경로(`applicant.name`)라서, 직접 정한 키(`성명` 등)도 되는지는 모델 서버에 직접 물어 확인해 보세요.
- 표의 행은 `debts.0.balance`, `debts.1.balance`처럼 번호를 붙인 키로 물었습니다.

**답 예** (평가 세트 2.0부터 값과 위치를 함께 답합니다)
```json
[{"key": "applicant.name", "value": "남궁예태", "bbox_2d": [212, 148, 318, 171], "page": 1},
 {"key": "loan.amount", "value": "301,000,000", "bbox_2d": [640, 402, 790, 425], "page": 1},
 {"key": "applicant.email", "value": null}]
```
- 값은 문서 표기 그대로입니다(쉼표, `원`, `금 ○○원정` 포함). 여러 줄 값은 `\n`이 들어갑니다.
- 빈 칸은 `{"key": 키, "value": null}`입니다 (위치 없음).
- 채점은 값 점수(`f1`), 위치 점수(`loc_f1`: 같은 키·같은 쪽에서 IoU 0.5 이상), 값+위치 점수(`vl_f1`, 주 점수) 셋입니다 ([benchmark.md](benchmark.md)).

**학습한 범위:** 한 질문에 항목 최대 40개입니다. 더 많으면 나눠 물으세요. 체크박스·도장·서명은 kie가 아니라 marks로 묻습니다.

## marks — 체크박스·도장·서명

**질문**
```
이 문서의 체크박스·도장·서명 상태와 위치를 확인해 JSON 목록으로 답하세요. 좌표는 그 쪽 이미지 기준 0~1000 정수, 쪽 번호는 1부터입니다.
- 체크박스: 체크된 보기마다 {"key": 키, "value": 보기 글자, "bbox_2d": 체크된 □ 위치, "page": 쪽}. 체크된 것이 없으면 {"key": 키, "value": null}
- 복수 선택: 체크된 보기마다 한 줄 (위와 같은 꼴)
- 도장·서명: {"key": 키, "value": true 또는 false, "bbox_2d": 찍힌 자리, "page": 쪽} (비어 있으면 value 만 false)
항목
{items}
```
`{items}`는 한 줄에 하나씩 종류에 따라 이렇게 씁니다.
```
- housing: 주택소유구분 (체크박스, 보기: 자가 / 전세 / 월세 / 기타)
- products: 가입상품 (복수 선택, 보기: 예금 / 적금 / 펀드)
- seal.applicant: 신청인 (도장)
- sign.applicant: 신청인 (서명)
- seal.customer: 신청인 (고객 도장, 도장)
```
- 괄호 앞쪽에는 kie와 같은 설명(누구의 무엇·몇 번째 행)이 있으면 붙습니다.

**답 예**
```json
[{"key": "housing", "value": "자가", "bbox_2d": [301, 512, 318, 529], "page": 1},
 {"key": "products", "value": "예금", "bbox_2d": [205, 610, 222, 627], "page": 1},
 {"key": "products", "value": "펀드", "bbox_2d": [405, 610, 422, 627], "page": 1},
 {"key": "seal.applicant", "value": true, "bbox_2d": [820, 880, 905, 950], "page": 2},
 {"key": "sign.applicant", "value": false}]
```

## freetext — 기타 칸 정리

기타·비고·사유·용도 칸에 사람이 대충 쓴 글을 DB에 넣을 칸으로 정리합니다. `kie`가 "적힌 그대로"를 묻는다면 이 과제는 "정리한 값"을 묻습니다. 같은 칸이 두 과제에 다 나올 수 있습니다.

**질문**
```
이 문서의 '{label}' 칸에 적힌 내용을 DB에 넣을 수 있게 정리해 JSON 한 줄로 답하세요. 기준일(서류 작성일)은 {basis} 입니다.
쓸 수 있는 키
- purpose: 용도. 보기 중 하나: {purposes}
- reason: 사유. 보기 중 하나: {reasons}
- amount: 금액. 원 단위 정수 (3천만원 → 30000000)
- date: 날짜. YYYY-MM-DD. 상대 날짜는 기준일로 계산 (초 = 1일, 중순 = 15일, 말 = 말일, 다음주 = 7일 뒤)
- period_months: 기간. 개월 수 정수 (1년 → 12)
- request: 요청. 보기 중 하나: {requests}
- memo: 위 키에 맞지 않는 내용. 적힌 그대로
- approx: 대략적인 값(정도, 쯤, 약, 초·중순, 다음주 등)을 쓴 키의 목록
적힌 내용만 쓰고 null 은 쓰지 않습니다. 대략적인 값도 가장 그럴듯한 값 하나로 쓰세요.
```
- `{label}`은 칸의 항목명(`비고`, `기타`, `해지사유`, `자금용도` …), `{basis}`는 상대 날짜를 계산할 기준일(`YYYY-MM-DD`)입니다. 합성 데이터는 서류 작성일이고, 실서류는 접수일 등 아는 날짜를 넣으세요.
- `{purposes}`: 생활자금, 주택구입, 전세자금, 사업자금, 학자금, 자녀 교육비, 의료비, 결혼자금, 차량구입
- `{reasons}`: 만기 해지, 해외 이주, 타행 이체, 급여 수령, 본인 요청, 계좌 정리, 주소 변경, 분실
- `{requests}`: 서류 추가 제출, 전화 연락, 우편 발송, 문자 안내, 방문 예정
- 보기 목록은 `docgen/freetext.py`에 있습니다. 질문은 `docgen.bench.prompts.freetext_prompt(칸 이름, 기준일)`로 만들면 학습과 같습니다.

**답 예** (기준일 2026-10-24, 칸: `[비고] 생활비로 3천 정도, 1년 쓰고 다음달 말까지 추가서류 낼게요`)
```json
{"purpose": "생활자금", "amount": 30000000, "period_months": 12, "date": "2026-11-30", "request": "서류 추가 제출", "approx": ["amount"]}
```
- 적히지 않은 키는 쓰지 않습니다 (null 없음). `approx`는 대략적인 값이 있을 때만 씁니다.
- `memo`는 다른 키에 맞지 않는 말을 적힌 그대로 씁니다 (예: `배우자 동의함`).

**학습한 범위:** 하나은행 원본 서식·가져온 서식(overlay)의 칸 이름이 `비고`·`기타`·`특기사항`·`요청사항`·`…사유`·`(자금)용도`·`목적` 인 글자 칸 중 약 40%에 글을 넣었습니다. 글은 칸 종류별 문장 틀 130여 개(`docgen/freetext_templates.json`)로 만들고, 칸에 읽을 만한 크기로 들어가지 않으면 더 짧은 틀로 바꾸거나 넣지 않습니다. 실제 기타 칸 글은 더 다양하니 실서류로 따로 평가하세요.

## classify — 서류 분류

**질문**
```
이 문서는 고객이 은행에 제출한 서류입니다. 서류의 정식 명칭(서류명)을 답하세요. 설명 없이 서류명만 한 줄로 답하세요.
```
**답:** `근로소득 원천징수영수증`
- 학습한 476종의 정식 명칭으로 답하도록 배웠습니다. 목록에 없는 서류에서 어떻게 답하는지는 확인하지 않았습니다.

## ocr_page — 전체 받아쓰기

**질문**
```
이 문서 이미지에 보이는 모든 글자를 빠짐없이 읽어 텍스트로 옮기세요. 위에서 아래, 왼쪽에서 오른쪽 순서로 쓰고, 표는 한 행을 한 줄로 쓰세요. 설명 없이 읽은 글자만 출력하세요.
```
**답:** 줄바꿈한 글자
- 학습 정답은 서류에 **채워 넣은 값들**을 줄마다 쓴 것입니다. 그래서 항목명이나 안내문 같은 서식 고정 문구는 빠질 수 있습니다.
- 서식 문구까지 위치와 함께 필요하면 OCR 과제의 `spotting`([tasks.md](tasks.md#ocr-과제))을 쓰세요.

## ocr_field — 값 칸 읽기

**질문**
```
이미지에 적힌 글자를 그대로 읽어 옮기세요. 설명 없이 읽은 글자만 출력하세요.
```
**답:** `서울특별시 서초구 강남대로 357` (여러 줄 값은 한 줄로 이어서)
- 값 칸 하나를 위아래 여백과 함께 잘라낸 이미지를 넣습니다. 손글씨도 학습했습니다.

## 하고 싶은 일 → 과제

| 하고 싶은 일 | 과제 |
|---|---|
| 업무에 필요한 서류가 다 왔는지 | `doc_check` |
| 서류끼리 내용이 맞는지, 전세사기·업계약 같은 관계 확인 | `cross_check` (전체), `review`의 예/아니오 질문 (한 가지만 콕 집어서) |
| LTV·나이·재직기간 등 숫자 확인 | `review` |
| 특정 값 뽑기 | `kie` |
| 동의 체크, 도장, 서명 여부 | `marks` |
| 기타·비고·사유 칸에 대충 쓴 내용을 DB 칸으로 | `freetext` |
| 무슨 서류인지 | `classify` |

패턴을 시험해 볼 때는 모델 서버(`swift deploy`, OpenAI 호환 API)에 위 질문 문장을 그대로 보냅니다. 이미지 크기는 [공통 규칙](#공통-규칙)대로 줄입니다.
- 평가 세트로 한꺼번에 물을 때는 `python -m train.cli predict`(학습 실행의 평가와 같음) 또는 `python -m docgen.bench run`이 같은 문장과 규칙을 씁니다.
- 저장된 답은 studio ⑥ 데이터셋(문항 탭)·⑦ 평가에서 정답과 나란히 봅니다.
