# 용어 한 장

문서·화면에 나오는 말을 모았습니다. **굵은 말**이 표준이고, "같은 말"은 예전 문서·화면·파일에 남아 있는 다른 이름입니다.

## 서식과 칸

| 말 | 뜻 | 같은 말 |
|---|---|---|
| **서식** | 서류 한 종류 (재직증명서, 대출거래신청서 …). 하나 = 폴더 `docgen/forms/<ID>/` 하나. 약 550종 | 양식, form |
| **html 서식** | 모양을 html 템플릿으로 그리는 서식. 행 수·쪽·글꼴이 문서마다 바뀜. 화면에서 고치지 않고 코드로 ([NEW_FORM_SPEC.md](../../docgen/manual/NEW_FORM_SPEC.md)) | 템플릿 서식, 공식대조 HTML(출처 표시) |
| **그림 서식** | 서식 그림(원본 PDF·이미지) 위에 값을 찍는 서식. 칸 위치가 고정. `hf###` = 하나은행 원본 PDF, `img_*` = 그림에서 그리거나 가져온 것. 고치는 화면 **영역 편집** | overlay, 원본 서식, 그린 서식, 이미지 서식 |
| **코드 서식** | 모양은 html 템플릿, 값은 파이썬 함수(`generate.py`)가 전부 만드는 서식 (재직증명서 등 처음 만든 70종). html 서식처럼 코드로 고침 | 화면 태그 `html · builtin` |
| **칸** | 서식에서 값이 들어가는 곳 하나 (글자 칸, 체크 보기, 서명·도장 자리, 표의 한 칸) | 영역, 자리, 값 칸, 필드 |
| **키** | 정답 JSON 에서 칸을 가리키는 영어 이름 (`customer.name`). 서식마다 그 서식 파일에 적힌 그대로 씀 (모든 서식이 같이 쓰는 키 사전은 없음). [keys.md](../studio/keys.md) | key |
| **키 설명** | 칸이 무엇을 읽는지 적은 말. 보통 서식에 인쇄된 칸 이름 (`성명`). 질문에 `- 키: 키 설명` 줄로 나감. 파일에서는 `label` | 항목명, label |
| **생성 방법** | 문서를 만들 때마다 칸에 넣을 값을 만드는 규칙 (고객 이름, 날짜, 보기 중 하나 …). 파일에서는 `fields.json` 의 `source`. [generators.md](../studio/generators.md) | 값 출처, source |
| **값 종류** | 칸 값의 꼴 (날짜·금액·전화 …). 생성 방법이 "자동"이면 이것대로 만듦. 파일에서는 `kind`. 여러 서식이 같이 쓰는 것은 `docgen/forms/_common/key_rules.json` 의 `kinds` (고르기 창의 "공통 값 종류") | kind |
| **표기** | 날짜·금액을 찍는 꼴 (`250131`, `1,234,000원`). 파일에서는 `fmt` | 형식 |
| **칸끼리 관계** | 칸마다 따로 만든 값을 서로 맞추는 것 (합계 = 행의 합, 시작일 ≤ 종료일). 서식 폴더 `generate.py` 의 `adjust` | adjust, 생성 스크립트 |
| **표** | 행 수가 서류마다 다른 반복 목록 (거래내역). 정해진 개수의 격자는 표가 아님 | 반복 행, 목록 |
| **자유 위치 도장·번호** | 접수인·일부인·Ref No 처럼 서류마다 아무 데나 찍히는 것 | floats |
| **검수 완료** | 사람이 그림·정답을 눈으로 보고 서식에 표시한 것 (서식 › 생성 사례 › 검수). 자동 검사 통과와 다름 | 리뷰 |
| **배정** | 서식을 평가 전용으로 둘지. 평가 전용이면 학습 데이터를 만들 때 그 서식을 뺌 | split |

## 데이터

| 말 | 뜻 | 같은 말 |
|---|---|---|
| **가짜 고객** | 생성기가 지어낸 고객 한 명 (이름·주소·직장 …). 한 서류 안의 값은 서로 맞음. 데이터셋에서는 서류 한 건마다 다른 고객 | 프로필, profile |
| **seed** | 가짜 고객과 무작위 선택을 정하는 번호. 같은 seed → 같은 문서. 데이터셋에서는 seed 와 서식 ID 로 고객을 정해, 같은 seed 라도 서식마다 다른 고객 | |
| **문항** | 그림 + 질문 + 정답 한 개 (`tasks/<과제>.jsonl` 의 한 줄) | 샘플, item |
| **과제** | 문항의 종류: `classify` 분류, `kie` 값 추출, `marks` 체크·도장·서명, `table`·`table_read`·`table_find`·`table_qa` 표, `freetext` 기타 칸 정리, `form_qa` 서식 전용 질문, `ocr_*` 글자 읽기. 모두 서류 한 건으로 묻습니다. [benchmark.md](benchmark.md) | task |
| **레시피** | 데이터셋을 만드는 설정 (어떤 서식, 몇 건, 촬영 조건). `docgen/recipes/<이름>.json` | recipe |
| **데이터셋** | 한 번 만든 문항 묶음 = 폴더 하나 (`<저장 폴더>/workspace/datasets/<이름>/`) | |
| **평가 세트 / 학습 데이터** | 데이터셋의 용도. 평가 세트는 고정해서 모델 비교에, 학습 데이터는 학습에. 서로 다른 가짜 고객 | 벤치마크 / train |
| **촬영 조건** | 원본·스캔·촬영·팩스처럼 그림을 흔드는 정도 | condition |

## 학습·결과

| 말 | 뜻 |
|---|---|
| **SFT** | 정답을 보여 주며 따라 하게 하는 학습 (이 저장소의 학습은 SFT 만) |
| **workdir** | 학습 한 번의 결과 폴더 (모델·점수·보고서). 실험 묶음에서는 `<root>/<label>/` |
| **실험 묶음** (sweep) | 평가 세트를 고정하고 모델마다 바꿀 것만 적어 여러 학습을 돌리는 것 ([sweep.md](../train/sweep.md)) |
| **캐시** (`cache_dir`) | 평가 세트 준비본·줄인 그림·모델 답을 실험끼리 같이 쓰는 폴더. 같은 모델·세트는 다시 추론하지 않음 |
| **채점 함수** (`scorer`) | 평가 세트를 기본과 다르게 채점하는 파이썬 함수 (`train/scorers/`) |
| **기준 모델** (`baseline`) | 보고서에서 다른 모델의 점수 차이(%p)를 잴 기준이 되는 모델. 실험 묶음·평가만 하기 설정의 `baseline` (기본 첫 모델) |
| **%p** | 점수 차이 (퍼센트 포인트). 70% → 75% 는 +5%p |
| **F1** | 맞힌 것과 빠뜨린 것을 함께 본 점수 (0~1, 높을수록 좋음). 값 추출·표 |
| **CER** | 글자 오류율 (0 에 가까울수록 좋음). OCR |
| **IoU** | 박스가 겹친 정도 (0~1). 위치 |

## 어디서

| 곳 | 하는 일 |
|---|---|
| **studio** | 웹 화면. 서식·새 서식·데이터셋 ([studio.md](../studio/studio.md)). 도커 컨테이너 `docgen-studio` 에서 돎 |
| **학습 서버** | GPU 가 있는 곳. 학습·평가 (`python -m train`), 모델 써 보기 (`python -m playground`) |
| **저장 폴더** | studio 와 학습 서버가 같이 보는 폴더. 데이터셋·학습 결과가 쌓임 (studio 안에서는 `/out`) |
