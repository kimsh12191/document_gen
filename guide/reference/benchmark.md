# 과제와 채점 규칙 (참고)

평가 세트·학습 데이터의 과제마다 **무엇을 묻고, 답이 어떤 꼴이고, 어떻게 채점하는지**입니다. 찾아볼 때 읽는 문서입니다.
만들기는 [데이터셋 만들기](../studio/data.md), 평가 세트·채점 함수 붙이기는 [sweep.md 2절](../train/sweep.md#2-평가-세트-databenchmark), 점수 읽기는 [sweep.md 5절](../train/sweep.md#5-결과),
질문 문장 원문은 [questions.md](questions.md), 과제별 실제 문항은 [tasks.md](tasks.md). 코드는 [docgen/bench/](../../docgen/bench).

두 가지를 따로 잽니다.

- **OCR:** 글자를 읽는 능력
- **문서 이해:** 서류를 알아보고 값을 뽑는 능력

공통: 답 앞의 생각 블록(`<think>…</think>`)은 떼고 채점합니다. 답이 없거나 형식을 못 읽으면 0점(CER 은 1)이고 답 형식 오류로 따로 셉니다
(빈 답이 빈 칸(null)이나 "도장 없음"을 우연히 맞히지 않게).

## 과제

| 영역 | 과제 | 입력 → 출력 | 주 지표 |
|---|---|---|---|
| OCR | `ocr_field` | 값 칸 하나를 잘라낸 이미지 → 적힌 글자 | 완전 일치율 (CER 함께 보고) |
| OCR | `ocr_page` | 서류 전체(여러 쪽) → 전체 받아쓰기 | 값 재현율: 정답 값이 받아쓴 글에 들어 있는 비율 |
| 문서 이해 | `classify` | 서류 → 서류명 | 정확도 |
| 문서 이해 | `kie` | 서류 + 항목 목록(키·항목명) → 값과 위치 목록 `[{key, value, bbox_2d, page}]` | 값+위치 F1 (값 F1·위치 F1·항목 정확도 함께) |
| 문서 이해 | `marks` | 서류 + 체크박스·도장·서명 목록 → 상태와 위치 목록 | 값+위치 F1 (항목 정확도·위치 F1 함께) |
| 문서 이해 | `freetext` | 서류 + 칸 이름·기준일 → 그 칸의 자유 기재를 DB 칸으로 정리한 JSON | F1 (지어낸 키 비율 함께) |
| 문서 이해 | `form_qa` | 서류 + 서식 폴더 `qa.py` 가 정한 질문 → 숫자·예/아니오·글·JSON | 정확도 |
| 문서 이해 | `table` | 서류 + 표를 가리키는 말 + 열 목록(키·항목명) → 모든 행 `{"columns", "rows", "row_boxes"}` (행 수는 모델이 정함) | 칸 F1 |
| 문서 이해 | `table_read` | 서류 + 표를 가리키는 말 → 머리글까지 그대로 (같은 꼴, 열을 정해 주지 않음) | 칸 F1 |
| 문서 이해 | `table_find` | 서류 → 표 목록 `[{"columns", "bbox_2d", "page", "n_rows"}]` | 위치 F1 (IoU 0.5) |
| 문서 이해 | `table_qa` | 서류 + 표를 가리키는 말 + 질문 → 행 수·조건 행 수·찾기·몇 번째 행·합계 | 정확도 |

### OCR

- **`ocr_field`:** 서류마다 값 칸 6개를 골라 잘라냅니다(위아래 여백 포함).
  - 결과는 글씨(`print` 인쇄체 / `hand` 손글씨), 촬영 조건, 값 종류(이름·주민번호·금액·날짜·주소 …), 손글씨 정정 여부로 나눠 봅니다.
  - 손글씨는 하나은행 원본 서식(`hf*`)에서 나옵니다.
- **`ocr_page`:** 전체 정답 글자가 없어서 "문서에 적힌 값이 받아쓴 글에 들어 있는가"로 잽니다.
  - 공백은 무시합니다.
  - `recall_fuzzy`는 값 길이의 20%까지 글자가 틀려도 찾은 것으로 셉니다.
  - 서식의 고정 문구(항목명, 안내문)는 채점하지 않습니다.

### 문서 이해

- **`classify`:** 서류명을 자유롭게 답하게 하고, 공백·문장부호를 뺀 뒤 정식 명칭과 같으면 맞습니다.
  - `acc_lenient`는 답 안에 정식 명칭이 들어 있으면 맞은 것으로 셉니다.
- **`kie`:** 항목 키와 항목명을 질문에 같이 줍니다. 그래서 학습하지 않은 모델도 같은 조건으로 잴 수 있습니다. 표(반복 행)는 묻지 않고 `table` 이 묻습니다 ([표의 정의](#표의-정의)). 문항의 30%에는 서류에 없는 항목이 섞여 있습니다 (정답 `null`, [빈 답 배우기](#빈-답-null-배우기)).
  - 키가 많은 서류는 40개까지만 묻습니다.
  - 빈 칸은 `null`이 정답입니다.
  - 값은 **타입에 맞춰 비교**합니다.
    - 날짜: `2025년 9월 20일` = `2025-09-20`
    - 금액: `금 오억원정 (₩500,000,000)` = `500000000`, `327,000,000원` = `327,000,000`. 1원만 달라도 틀립니다.
    - 번호(전화·주민·계좌): 숫자만 비교
    - 그 밖: 대소문자·공백·문장부호 무시. 글자가 하나라도 다르면 틀림
  - 중첩 JSON(`{"loan": {"amount": ...}}`)으로 답해도 점 경로로 펴서 채점합니다.
  - 실서류처럼 비교 기준이 다른 평가 세트는 세트마다 채점 함수를 붙입니다 ([eval.md 2절](../train/steps.md)).
  - 서식 폴더의 `questions.json` 에서 답 틀(`answer`)을 바꾼 서식은 그 꼴로 채점합니다. JSON 틀에 `{bbox_2d}` 가 없으면 위치 점수 없이 값 F1, 줄글 틀(`"{label}: {value}"`)이면 줄에서 값을 찾아 값 F1 ([서식 폴더 설명서 5절](../../docgen/forms/README.md#5-질문과-답-고치기)). 지금은 모든 서식이 기본 틀입니다.
  - **위치:** 항목마다 `bbox_2d`(그 쪽 이미지 기준 0~1000 정수, OCR 과제와 같은 좌표)와 `page`(1부터)를 답합니다. 빈 칸은 `{"key", "value": null}`로 위치 없이 답합니다.
    - 값 점수(`f1`): 위치는 보지 않습니다. 위치를 못 내는 모델도 잽니다 (값만 담은 객체로 답해도 됨).
    - 위치 점수(`loc_f1`): 같은 키·같은 쪽에서 IoU 0.5 이상인 짝 (OCR 과제의 짝짓기와 같음).
    - 값+위치 점수(`vl_f1`, 주 지표): 박스도 맞고 값도 맞은 항목.
- **`marks`:** 체크된 보기 글자, 복수 선택 목록, 도장·서명 true/false를 맞힙니다.
  - 목록으로 답합니다: 체크된 보기마다 `{key, value: 보기 글자, bbox_2d: 체크된 □, page}`, 체크된 것이 없으면 `{key, value: null}`, 도장·서명은 `{key, value: true/false, bbox_2d: 찍힌 자리}`. 점수는 `kie`와 같이 값(`acc`)·위치·값+위치(주 지표).
  - 은행 직원 결재란(담당·책임자·본인확인 등)도 항목에 들어갑니다. 키가 `seal.staff.책임자`처럼 `staff`를 포함하고, 직원 도장·서명이 찍혔는지를 묻습니다. 고객 도장 칸 옆의 직원 도장을 고객 도장으로 착각하지 않는지도 함께 봅니다.
- **`freetext`:** 기타·비고·사유·용도 칸에 대충 쓴 글을 정해진 키(`purpose`, `reason`, `amount`, `date`, `period_months`, `request`, `memo`, `approx`)로 정리합니다. 질문과 보기는 [questions.md](questions.md#freetext--기타-칸-정리).
  - 글과 정답은 `docgen/freetext.py`가 같이 만듭니다. 칸 종류(용도·사유·비고)별 **문장 틀 130여 개**(`docgen/forms/_common/freetext_templates.json`, 예: `재직증명서 {date}까지 가져오기로 함`, `{purpose}(으)로 {amount} 필요`)에서 하나를 골라 자리를 채우고(`3천 정도`, `담달 말`, `애 학원비` …), 채운 값과 틀에 정해 둔 값이 정답입니다. 금액은 용도에 맞는 범위에서 뽑습니다. 원본·가져온 서식(overlay)의 해당 칸 약 40%에 들어갑니다. 틀은 사람이 더하거나 고쳐도 됩니다 (테스트가 형식을 검사).
  - 키마다 맞는지 봅니다. 금액·기간은 숫자가, 날짜는 `YYYY-MM-DD` 글자가, 용도·사유·요청은 보기 글자가 정확히 같아야 맞습니다. `memo`만 띄어쓰기·문장부호 차이를 허용합니다. **`kie`처럼 표기가 달라도 같은 값으로 봐 주지 않습니다** — DB에 넣을 꼴로 정리하는 것이 과제이기 때문입니다.
  - `f1`(주 지표): 맞힌 키 / (정답 키, 답한 키). 정답에 없는 키를 답하면 정밀도가 떨어집니다.
  - `extra_key`: 답한 키 중 정답에 없는 키(글에 없는 내용을 지어냄)의 비율. 낮을수록 좋습니다.
  - `approx_acc`: `approx` 목록이 정답과 같은 비율. `doc_exact`: 키·값·`approx`가 모두 맞은 비율.
  - 결과는 서식 그룹·글씨·난이도(`level`: `short` 값 나열 / `sentence` 문장 / `relative` 상대 날짜 / `approx` 대략)·키별로 나눠 봅니다.
- **`form_qa`:** 서식 폴더의 `qa.py` 에 적은 함수 하나가 질문 하나입니다 (`qa.py` 가 있는 서식에서만 생김, 지금은 없음). 문항의 `meta.question` 은 `<서식ID>.<함수 이름>`.
  - 정답 꼴로 채점합니다: 숫자는 숫자가 같은지, 예/아니오는 그대로, 글은 띄어쓰기·문장부호 무시, JSON은 칸마다. 주 지표 `acc`.
  - 질문 몇 개만 다르게 채점하려면 `train/scorers/` 의 채점 함수를 평가 세트에 붙입니다 (견본 `train/scorers/form_qa_example.py`, [eval.md 2절](../train/steps.md)). 쓰는 법은 [서식 폴더 설명서 5절](../../docgen/forms/README.md#5-질문과-답-고치기).

### 표의 정의

**항목 묶음(열 구성)은 서식이 정하고, 그 묶음이 몇 번 나오는지(행 수)가 서류마다 다른 것만 표입니다.** 나머지는 모두 `kie`(체크·도장·서명은 `marks`)가 묻습니다.

| 경우 | 예 | 어디로 |
|---|---|---|
| 행이 늘어나는 표 | 자격득실 이력, 거래내역, 품목 | 표 |
| 열이 늘어나는 표 | 연도별 납부 내역이 가로로 | 표 (질문에 "열마다 한 건") |
| 이 서류에는 한 행뿐 | 담보 목록 1건 | 표 (늘어날 수 있는지가 기준) |
| 빈 행이 인쇄된 표 | 5행 양식에 2행만 적음 | 표, 적힌 2행만 |
| 표 모양이 아닌 반복 묶음 | 보증인 1 / 보증인 2 …, 상속인 목록 | 표 (목록) |
| 항목명·값이 번갈아 있는 양식형 표 | 성명 │ 홍길동 │ 주민번호 │ … | `kie` (레코드가 하나) |
| 개수가 정해진 격자 | 결재란, 3×4 금리표, 늘 "최근 3년" 인 칸 | `kie` |
| 표 안의 합계·소계, 표 위의 머리 정보 | 거래내역 합계, 계좌번호·조회 기간 | `kie` |

- **데이터에서는** 키에 행 번호가 든 칸(`rows.0.kind` → 묶음 `rows`, 열 `kind`)이 표 칸이고 `kie`에서 빠집니다 (`docgen/bench/tasks/__init__.py` 의 `Doc.tables`). 개수가 정해진 격자는 서식 `questions.json` 에 `{"table": {"<묶음>": {"ask": false}}}` 로 적어 `kie`에 남기고, 표 제목은 `{"title": "…"}` 로 적습니다 (없으면 머리글·위치로 가리킴).
- 표 안에 표가 든 겹친 목록(`items.0.specs.1.no`)은 묻지 않습니다 (4종). 키 이름에 번호를 붙여 반복한 칸(`guarantor1.name`, 원본 서식의 `Fund2`)은 아직 표로 묶이지 않아 `kie`가 묻습니다 — 서식마다 고칠 목록은 표 점검 목록 (`python -m docgen.bench.table_audit`).

### 표 과제

네 과제가 같은 표(`Doc.tables`)에서 나오고, 답 꼴이 같습니다: `{"columns": [열], "rows": [[값, …], …], "row_boxes": [{"bbox_2d", "page"}]}`.

- **공통 규칙** (질문에 적고 정답도 그대로): 행은 문서에 보이는 순서(위→아래, 쪽 순서), 여러 쪽이면 한 목록으로 이음, 다시 나온 머리글 행·모두 빈 행은 뺌, 칸 안의 여러 줄은 공백 하나, 여러 행에 걸친 칸은 행마다 같은 값, 빈 칸은 `null`.
- **표를 가리키는 말:** 제목(`questions.json` 에 있을 때) / 머리글 두어 개 / 위치(쪽·bbox) / 표가 하나뿐이면 "표" 중 무작위.
- **`table`:** 열을 키·항목명으로 줍니다. 넣은 이미지에 보이는 행은 늘 전부 묻습니다 (4.1 까지는 30행 넘는 표·여러 쪽 표 일부를 "N쪽에 있는 행만"·"앞에서부터 30행까지만" 으로 잘라 물었음, 한 쪽만은 [한 쪽 문항](#여러-쪽-서류-한-쪽만--모든-쪽)). 문항의 30%에는 그 표에 없는 열을 하나 섞습니다 (같은 그룹 다른 서식의 열, 정답은 그 열 전부 `null`). 합계·소계 행은 뺍니다.
  - 채점: 정답 행과 답한 행을 순서대로 짝짓고(빠지거나 더 들어간 행 허용, 맞은 칸 비율의 합이 가장 큰 짝) 칸 단위로 셉니다. `cell_f1`(주 지표)·`cell_precision`·`cell_recall` (정답이 빈 칸인데 값을 쓰면 틀림), `row_exact` 행 완전 일치, `count_acc` 행 수 일치, `loc_f1` 행 상자 (같은 쪽·IoU 0.5), `absent_null` 섞은 없는 열을 `null` 로 둔 비율.
- **`table_read`:** 열을 주지 않고 머리글까지 그대로 옮깁니다. 정답은 그릴 때 브라우저에서 읽은 `<table>` 구조(html 서식만)입니다. 머리글 줄이 여럿이면 `위 > 아래`, 여러 열에 걸친 칸은 첫 열에만, 합계 행은 그대로 둡니다. 다른 값 칸이 섞인 표·겹친 표는 묻지 않습니다. 채점은 머리글을 글자로 짝지은 뒤 `table` 과 같은 칸 F1, 그리고 `header_f1`.
- **`table_find`:** 표마다(여러 쪽이면 쪽마다) 머리글·위치·쪽·행 수. 표가 없는 서류도 15% 묻습니다 (정답 `[]`). 채점: 같은 쪽·IoU 0.5 짝 F1(주 지표), `count_acc` 표 수, `rows_acc` 행 수, `header_f1`.
- **`table_qa`:** 표마다 질문 둘 — 행 수, 조건에 맞는 행 수, 찾기(행마다 다른 열의 값으로), 몇 번째 행, 마지막 행, 합계(금액·숫자 열). 채점: 숫자는 같은 수, 칸 값은 `kie` 와 같은 비교.

### 여러 쪽 서류: 한 쪽만 / 모든 쪽

여러 쪽 서류는 문항을 두 경우 중 하나로 만듭니다 (4.2 부터).

| `meta.view` | 넣는 이미지 | 정답 | 비율 |
|---|---|---|---|
| `page` | 한 쪽 (무작위) | 그 쪽에 있는 칸·행·글만. 위치의 `page` 는 1. 문항 ID 끝에 `_p<쪽>`, `meta.page` 그 쪽, `meta.n_pages_doc` 서류 쪽 수 | 레시피 `page_view` (기본 0.5) |
| `all` | 모든 쪽 | 모든 쪽 | 나머지. 한 쪽 서류는 늘 `all` |

- 한 쪽에 묻을 것이 없는 과제는 그 문항을 만들지 않습니다 (예: 2쪽에 표 꼬리·서명만 있으면 `kie` 없음). 분류는 별지 한 쪽만 보고도 묻습니다.
- 채점 보고서는 `view` 로 갈라 볼 수 있습니다 (`docgen/bench/tracking.py`).
- 카드·studio 미리보기는 늘 모든 쪽입니다.

### 빈 답 (null) 배우기

실제로 쓸 때는 정해진 키 목록으로 묻고, 서류에 없거나 비었거나 가려진 칸은 `null` 이어야 합니다. 평가 세트 3.1 의 `kie` 정답은 약 35% 가 `null` 이었지만 대부분 원본 서식(`hf###`)의 빈 칸과 표의 빈 행이었고, 코드·html 서식의 표 밖 칸은 약 9% 뿐이었습니다. 서류에 없는 키를 묻는 문항과 가린 칸은 없었습니다. 4.0 부터 아래 셋을 더합니다. 545종 한 건씩 만들어 보면 `kie` 정답의 `null` 은 원본 서식 35%, 코드·html 서식 12.5%, 그중 없는 칸이 약 4%, 가린 서류는 약 11% 입니다.

| | 무엇 | 기본 | 바꾸는 곳 |
|---|---|---|---|
| 없는 키·열 | `kie` 문항의 30%에 그 서류에 없는 칸 1~3개(같은 그룹 다른 서식의 칸, 항목명이 서류의 칸과 겹치지 않는 것, 생년월일처럼 다른 값으로 짐작할 수 있는 것은 뺌), `table` 문항의 30%에 없는 열 하나. 정답 `null` | 30% | `kie.py`·`table.py` 의 `ABSENT_RATE`, 후보 `docgen/bench/absent.py` |
| 비어 있기도 한 칸 비우기 | 항목명이 용도·비고·메모·참고·특기사항·기타·발급번호·문서확인번호·팩스·이메일·홈페이지·자택/직장전화·영문성명 인 칸을 칸마다 30% 비움 (자유 기재 글이 든 칸은 빼고). 항목명은 그대로 인쇄됨 | 0.3 | 레시피 `"nulls": {"blank": …}`, `--blank` (`docgen/render.py` `OPTIONAL_LABEL`) |
| 가림 | 서류의 10%에서 값 칸 1~3개를 검은 상자로 가리고 정답 `null` (이름·주민번호·연락처·계좌·주소·등록번호 먼저) | 0.1 | 레시피 `"nulls": {"mask": …}`, `--mask` |

- 가린 칸은 `ocr_page`·`ocr_field` 정답에서도 빠집니다. 문항 `meta.masked` 에 가린 칸 수, `eval.absent` 에 섞은 없는 키·열이 남습니다.
- 비식별 처리한 실서류 평가 세트는 가린 칸의 정답을 `null` 로 두거나 채점에서 뺍니다.

## 평가 세트

지금 세트의 과제별 문항 수는 studio **데이터셋 › 그 데이터셋 › 구성** 또는 폴더의 `meta.json`.

- **고정 seed:** 같은 설정이면 언제 만들어도 같은 세트가 나옵니다(같은 코드 기준). `--workers` 수와도 상관없습니다.
  - 평가 세트는 고객 seed `1,000,000`부터, 학습 데이터(`--split train`)는 `10,000,000`부터 씁니다 (서로 겹치지 않게).
- **세트 버전:** `meta.json`의 `version`이 다른 세트끼리는 점수를 바로 비교하지 않습니다 (서식·질문·정답 꼴이 바뀌었을 수 있음). 생성기 코드가 바뀌면 평가 세트와 학습 데이터를 같은 코드로 새로 만듭니다.
- **촬영 조건:** 서류마다 깨끗한 원본 50%, 스캔 20%, 촬영 15%, 팩스 15%입니다. 위치 정답은 증강에 맞춰 옮깁니다.
- **기록:** `meta.json`에 만든 설정, 생성기 커밋, 과제별 문항 수가 남습니다. 결과를 비교할 때는 같은 `meta.json`의 세트인지 확인하세요.

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--out` | bench_out | 만들 폴더. 비어 있지 않으면 멈춤 (`--force` 로 다시 만들기) |
| `--recipe` | — | 레시피 JSON (`docgen/recipes/*.json`): 위 설정과 묶음 구성 규칙·빼는 서식(`exclude`)·검수 완료 서식만(`reviewed_only`) |
| `--types` | all | 쓸 서류 (ID, 그룹명) |
| `--per-doc` | 1 | 서류 종류마다 샘플 수 |
| `--fields-per-doc` | 6 | 서류마다 `ocr_field` 문항 수 |
| `--max-keys` | 40 | `kie`·`marks` 한 문항에 묻는 최대 항목 수 |
| `--scale` | 2.0 | 이미지 배율 (A4 한 쪽 약 1588×2246) |
| `--workers` | 1 | 동시에 렌더링할 프로세스 수. 결과는 같고 빨라집니다 (프로세스마다 Chromium 하나) |
| `--split` | test | `train`이면 학습 데이터 (seed 가 평가 세트와 겹치지 않음, `swift/` 도 만듦) |
| `--start` | 0 | seed 시작 번호. 학습 데이터를 나중에 더 만들 때 씁니다 |
| `--blank` | 0.3 | 비어 있기도 한 칸을 비우는 비율 ([빈 답 배우기](#빈-답-null-배우기)), 0 이면 끔. 레시피 `"nulls": {"blank": …}` |
| `--mask` | 0.1 | 값 칸 1~3개를 검은 상자로 가리는 서류 비율, 0 이면 끔. 레시피 `"nulls": {"mask": …}` |
| (레시피만) | 0.5 | `page_view`: 여러 쪽 서류에서 한 쪽만 넣고 그 쪽만 묻는 비율 ([여러 쪽 서류](#여러-쪽-서류-한-쪽만--모든-쪽)), 0 이면 늘 모든 쪽 |

### 문항 형식 (`tasks/<과제>.jsonl`)

```json
{"id": "kie/loan_application_1000000", "task": "kie",
 "images": ["images/loan_application_1000000.jpg"],
 "prompt": "이 문서에서 아래 항목의 값과 위치를 찾아 JSON 목록으로 답하세요. …\n- applicant.name: 성명\n- loan.amount: 대출신청금액 …",
 "answer": [{"key": "applicant.name", "value": "김나우", "bbox_2d": [264, 231, 384, 249], "page": 1},
            {"key": "loan.amount", "value": "56,000,000", "bbox_2d": [264, 270, 440, 288], "page": 1}],
 "eval": {"fields": {"loan.amount": {"type": "amount", "norm": 56000000, "kind": "amount"}}},
 "meta": {"doc_type": "loan_application", "group": "bank_form", "condition": "scan", "writing": "print", "n_pages": 1, "view": "all"}}
```

- `images`는 세트 폴더 기준 상대 경로이고, 질문 앞에 순서대로 넣습니다.
- `answer`는 정답이고, `eval`은 채점에 쓰는 추가 정보입니다.
- 다른 실행기(사내 추론 서버, ms-swift `infer` 등)를 쓰려면 예측을 `{"id": 문항 id, "output": "모델 출력"}` 꼴로 `<pred 폴더>/<과제>.jsonl`에 저장한 뒤 `eval`을 돌리면 됩니다.

## 해석할 때 주의

- **합성 서류입니다.** 서식·글꼴·증강이 실제 스캔본보다 단순합니다. 실제 서류 성능의 상한에 가깝게 보고, 실제 표본으로 따로 확인하세요.
- **학습 데이터와 같은 생성기입니다.** docgen으로 학습한 모델은 서식 분포를 이미 봤으므로 점수가 유리하게 나옵니다. 범용 모델과 비교할 때 이 점을 적어 두세요.
  - `--split train`으로 학습한 모델은 고객(seed)만 다를 뿐 **같은 서식·같은 질문 문장**을 봤습니다. 합성 평가 세트 점수가 크게 오르는 건 당연하고, 실서류 성능은 검수한 실서류 평가 세트로 따로 확인하세요.
- **`ocr_page`는 값만 셉니다.** 서식 고정 문구를 잘 읽어도 점수에 들어가지 않습니다.
- **`kie`는 항목명을 알려 줍니다.** "어떤 항목이 있는지 찾는" 능력은 재지 않습니다. 대신 없는 항목을 섞어 "없으면 null" 은 잽니다.
- **세트 버전 4.0 의 `kie` 는 3.1 과 바로 비교하지 않습니다.** 표 칸이 빠졌고(표는 `table`), 없는 항목·빈 칸·가린 칸이 늘었습니다.
- **세트 버전 4.1:** 원본 서식과 공식 대조 html 서식에서 한 묶음(`목록`)으로 섞이던 표 77종을 표마다 나눴고(키 `<묶음>_목록.<행>.<열>`), 표가 인쇄된 줄을 넘치면 별지 쪽에 이어 적습니다. 그 서식들의 표 문항·쪽 수는 4.0 과 다릅니다.
