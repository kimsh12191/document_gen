# 실문서 벤치마크

Studio의 **실문서 벤치마크** 탭에서 이미지 등록 → 포맷·추출 항목 → 추론·검수 → 벤치마크 확정을 한 작업 안에서 진행합니다. 합성 서식을 등록하거나 기존 서식 ID에 연결할 필요가 없습니다.

## 연결 설정

탭 오른쪽 **OCR·모델 연결**에서 한 번 설정합니다. 기존 `studio/config.json`의 `ocr`와 내부 OpenAI 호환 `providers`를 기본으로 불러옵니다. 화면에서 저장한 설정은 `<workspace_dir>/real_benchmark_connections.json`에 보관하며 기존 설정 파일은 수정하지 않습니다.

- OCR: 서버 주소(예: `http://ocr-server:30107`), OCR 버전. 기본 어댑터는 `studio.internal_ocr_adapter:ocr_from_file`이며 `/ocr`에 이미지를 보냅니다. 응답 형식이 다르면 상세 설정의 어댑터·매핑을 지정합니다. 서버·모델이 바뀌면 캐시 구분을 위해 버전도 바꿉니다.
- VLM: 연결 이름, 서버 주소(예: `http://vlm-server:8000/v1`), 서버가 제공하는 모델 이름. Studio 서버에서 해당 주소에 접속할 수 있어야 합니다. 인증이 필요하면 키 값을 넣지 않고 Studio 프로세스 환경변수 이름을 지정합니다.
- 연결 확인: OCR은 `/health`, VLM은 `/models`를 조회합니다. OCR 서버에 `/health`가 없다면 연결 확인 실패와 실제 OCR 실패는 구분해서 확인합니다.

VLM은 외부 vLLM 서버에서 별도로 실행합니다. Studio는 모델을 로드하지 않고 `/chat/completions`에 문서 이미지와 질문을 보냅니다. 이미지 파일은 요청에 포함하므로 VLM 서버와 이미지 폴더를 공유할 필요가 없습니다.

## 작업 순서

1. **이미지 등록**: 작업 이름과 파일 또는 서버 폴더를 지정합니다. 서버 폴더는 기존 `import_dir` 제한을 따릅니다. PDF 한 파일은 문서 하나, 이미지 한 파일은 문서 하나로 시작합니다.
2. **포맷·추출 항목**: 기존 OCR 글자·좌표 기반 묶기를 사용합니다. 썸네일을 보고 포맷을 합치거나 선택 문서를 별도 그룹으로 나눕니다. 여러 이미지가 한 문서의 연속 쪽이면 순서를 확인하고 **선택 이미지를 한 문서로** 묶습니다. 이 작업은 현재 가져온 파일 순서로 쪽을 정하므로 파일명에 쪽 순서를 넣으세요. 항목을 저장하기 전에 묶기를 마칩니다.
3. 포맷마다 이름과 **키 / 찾을 내용 / 타입**을 입력하고 저장합니다. 예: `applicant_name / 신청인 성명 / 글자`, `signed / 신청인 서명 / 서명 유무`. 글자·금액·숫자·날짜·단일 체크 선택·도장·서명을 지원합니다. 복수 체크는 보기별 위치를 따로 검수할 수 있도록 확장할 때 지원합니다. 저장하면 실제 추출 질문을 확인할 수 있습니다.
4. **추론**: 모델과 대상 포맷을 선택합니다. 성공 문서는 그대로 두고 실패·미실행 문서만 실행합니다. 파싱 실패·키 누락·잘린 응답은 성공으로 저장하지 않습니다. 작업 진행과 실패 문서·로그는 같은 화면에서 봅니다.
5. **검수**: 이미지 위 박스와 오른쪽 값을 수정합니다. 빠진 항목은 정의한 키 목록에서 추가합니다. 빈칸은 항목을 삭제하지 않고 값을 비워 둡니다. 도장·서명은 있음/없음을 확인합니다. 값이 있는 항목은 위치도 지정해야 검수 완료할 수 있습니다. `Ctrl+S`는 저장, `Ctrl+Enter`는 검수 완료 후 다음 미완료 문서입니다.
6. **확정**: 이름과 버전을 입력하면 검수 완료 문서만 복사해 고정 평가 세트로 등록합니다. 기본 과제는 `kie`, `marks`이고 문서 분류도 평가하려면 체크합니다. 정답 분류명은 사용자가 확정한 포맷 이름입니다. 결과는 기존 데이터셋·평가 화면과 `train`의 평가 데이터로 사용합니다.

추론 후에는 해당 포맷의 항목 정의를 잠급니다. 다른 항목 구성으로 평가하려면 새 작업을 만듭니다. 원래 모델 답과 사람 수정본은 따로 보관하고, 확정 폴더에는 이미지·항목 정의·모델 정보·실제 질문·추론 설정·원본 응답·검수 이력을 복사합니다. 작업을 나중에 수정해도 이미 확정한 버전은 바뀌지 않습니다.

## VLM으로 항목·키 제안

포맷의 **찾을 내용**에 `신청인 성명`, `대리인 성명`처럼 문서의 항목명을 적고 **VLM으로 항목·키 제안**을 누르면 키를 연결합니다. 입력한 항목명이 없으면 대표 문서에서 항목도 찾아 제안합니다. 대표 문서는 포맷 안에서 바꿀 수 있으며 여러 쪽이면 그 문서의 모든 쪽을 보냅니다.

대표 이미지와 함께 키의 개념(누구의 어떤 값인지), 공통 키 전체의 이름·의미·역할, OCR과 입력한 항목명에 관련된 문서별 키 후보를 보냅니다. 전체 자동 수집 키를 무제한으로 넣지 않고 기본 256개 이내로 후보를 고릅니다(공통 키는 항상 포함). 표에는 사용한 후보 수와 전체 키 수가 표시됩니다. 후보에서 빠진 관련 키가 있을 수 있으므로 새 키 제안도 사람이 확인합니다.

결과에는 **문서 표시명 / 추출할 내용 / 추천 키 / 기존·새 키 구분 / 제안 이유**가 나옵니다. 예를 들어 신청인 구역의 `성명`은 `customer.name`, 대리인 구역의 `성명`은 `agent.name`을 고르는 방식입니다. 의미와 역할이 맞는 기존 키가 없으면 새 키를 제안합니다.

기존 키는 기본 선택하고 새 키는 기본 선택하지 않습니다. 반영할 항목을 고른 뒤 **선택 제안을 항목에 반영**하고, 키·설명·타입을 수정한 다음 **추출 항목 저장**으로 확정합니다. 제안 자체는 항목 정의나 공통 키 사전을 변경하지 않습니다. 이미 추론을 시작한 포맷은 항목 정의가 고정되어 제안 버튼도 잠깁니다. 제안의 입력·실제 질문·키 후보 스냅샷·원본 응답은 `<workspace_dir>/real_benchmark_requests/`에 남깁니다.

## 내부 구성

- 작업: `<workspace_dir>/imports/<작업>/real_benchmark.json` (기존 `batch.json`, `pages.jsonl`, `formats.json` 공유)
- 원본 추론: 같은 작업의 `pred/<문서 해시>.json`
- 검수: `<real_data_dir 또는 기본 real_data>/real_bench/<작업>/reviews/`
- 평가 세트: `<workspace_dir>/datasets/<이름>-<버전>/`, 원본·검수 근거는 그 안의 `input/provenance/`

첫 버전은 OCR 기반 포맷 묶기와 문서 이해 과제에 집중합니다. VLM으로 포맷 경계를 재판단하는 기능과 서류 묶음의 심사·대조 정답 생성은 이 탭에 포함하지 않습니다.
