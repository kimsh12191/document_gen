# studio 사용법

studio 는 **서식을 보고 고치고**, **새 서식을 더하고**, **데이터셋(평가 세트·학습 데이터)을 만드는** 웹 화면입니다. 이 세 가지가 핵심이고 나머지 메뉴는 이를 돕습니다.
학습·평가는 studio 가 아니라 GPU 학습 서버에서 합니다 ([training.md](training.md)).

```text
  서식 ────────────────┐
   (보기·고치기·검수)    ├──▶  데이터셋  ──▶  학습 서버 (python -m train)
  새 서식 추가 ────────┘      (레시피로 만들기 → 문항 확인 → 학습 설정)
   (그림 위에 칸 그리기)
```

처음 보는 말(서식 종류, 칸, 키, 생성 방법, seed …)은 [용어 한 장](terms.md).

## 접속

설치 담당에게 받은 주소로 들어갑니다. 보통은 내부망 서버에 떠 있고, 윈도우 PC 에서 터널을 열어 브라우저로 `http://localhost:8765`:

```bash
ssh -N -L 8765:localhost:8765 <계정>@<서버IP>     # 이 창은 열어 둠
```

로그인이 없으므로 주소를 아무에게나 열지 않습니다. 띄우는 법은 [docker/README.md](../docker/README.md) (도커 없이 내 PC 에서는 [studio/README.md](../studio/README.md)).

## 왼쪽 메뉴

| 메뉴 | 언제 | |
|---|---|---|
| **서식** | 서식 545종을 보고, 값·위치·모양을 고치고, 검수 완료를 표시 | 1절 |
| **새 서식 추가** | 목록에 없는 서식을 그림에서 만듦 | 2절 |
| **데이터셋** | 레시피로 평가 세트·학습 데이터를 만들고, 문항을 보고, 학습 설정을 씀 | 3절 |
| 시나리오·묶음 | 업무(대출 신청 등)마다 필요한 서류·대조 사례·심사 규칙 | 4절 |
| 키 사전 | 칸 키의 "누구의 · 무엇", 공통 키, 값 종류 (보통 손대지 않음) | 4절 |
| 표시 요소 | 체크·도장·서명·자유 위치 도장이 나오는 확률 (모든 서식 공통) | 4절 |
| OCR 예시 · 사용 가이드 | OCR 과제 예, 이 설명서들 | |

## 1. 서식

**목록:** 검색(ID·서식명), 그룹·종류(html / overlay)·검수 상태로 거릅니다. 줄을 누르면 그 서식이 열립니다.
서식 이름으로 ID 를 찾으려면 [documents.md](documents.md).

**서식 하나**는 위 탭 넷으로 나뉩니다 (아래 줄은 그 탭 안의 화면).

| 탭 | 화면 | 여기서 하는 일 |
|---|---|---|
| **개요** | 요약 · 카드 원문 · 업무·시나리오 | 이 서식이 묻는 것(칸·표·체크), 검수 상태, 남은 문제. 처음 보는 서식은 여기부터 |
| **그림·검수** | 미리보기 · 여러 장 보기 · 검수 | 그림과 정답 박스가 맞는지 눈으로 봄. seed(가짜 고객)·촬영 조건을 바꿔 봄. **검수** 화면에서 자동 검사 경고를 보고 **[검수 완료]**, **배정**(평가 전용으로 두면 학습 데이터를 만들 때 이 서식을 뺌) |
| **질문·답** | 실제 문항 · 키 | 과제마다 실제로 나오는 질문·정답, 칸마다 키(누구의 · 무엇) |
| **고치기** | 그림 서식: 영역 편집 · 파일 / html 서식: 자리·템플릿 · 레이아웃·샘플링 · html 편집 · 파일 | 값·위치·모양을 고침. **레이아웃·샘플링**은 한 서식의 여러 모양 중 무엇이 얼마나 나올지, **html 편집**은 복제·새로 만든 html 서식의 템플릿, **파일**은 서식 폴더의 파일 내용 |

### 자주 하는 일

| 하고 싶은 것 | 순서 |
|---|---|
| 이 서식에서 무엇이 나오는지 보기 | 개요 › 요약 → 질문·답 › 실제 문항 |
| 그림·정답이 맞는지 검수 | 그림·검수 › 미리보기 (seed 몇 개, **문제 표시**를 켜고 이상한 곳을 눌러 남김) → 검수 › **[검수 완료]** |
| 값이 이상하게 나옴 (꼴·범위) | 고치기 › 영역 편집에서 그 칸을 누르고 **생성 방법 [고르기…]** / html 은 자리·템플릿에서 자리를 누르고 생성 방법 |
| 값 위치가 어긋남 | overlay: 영역 편집에서 칸을 끌어 옮김 · html: 자리·템플릿 |
| 칸 더하기·빼기 | overlay: 영역 편집에서 그리기·빼기 · html: 자리·템플릿에서 빈칸 누르고 **[자리 넣기]** |
| 질문 문장·답 모양, 이 서식만의 질문 | 화면이 아니라 파일 (`questions.json`, `qa.py`) → [서식 고치기 0절](../docgen/forms/README.md) |

고친 뒤에는 **미리보기**로 확인하고 다시 **검수 완료**를 누릅니다 (그림이 바뀌면 "재검수 필요"로 돌아감).

**"검수"는 두 가지입니다.** 서식의 **검수 완료**(이 서식의 그림·정답이 맞다고 사람이 표시, 위)와, 데이터셋을 만든 뒤 **데이터셋 › 문항**에서 문항 몇 개를 눈으로 보는 것(3절). 둘 다 사람이 하고, 자동 검사 통과와는 다릅니다.
무엇을 어느 파일에서 고치는지, LLM 에게 맡기는 법은 [서식 고치기](../docgen/forms/README.md).

**영역 편집**(overlay 서식) 화면: 가운데 그림 위의 칸을 눌러 고르고, 끌어서 옮기고, 모서리로 크기를 바꿉니다. 위 도구로 새 칸을 그리고, 오른쪽에서 고른 칸의 항목명·키·생성 방법을 정합니다.
**저장**을 눌러야 파일에 들어가고, 아래 **수정 전후 비교**로 저장본과 지금을 견줍니다. 도구 설명은 [new-forms.md 0절](new-forms.md#0-그림-위에-그려서-만들기-overlay).

## 2. 새 서식 추가

| | A. 그림 위에 그려서 (overlay) | B. 대형 모델로 html 서식 |
|---|---|---|
| 이럴 때 | 서식 그림이 있고 칸 위치가 고정된 서식 (대부분) | 행 수·쪽이 바뀌는 서식을 html 로 다시 짜야 할 때 |
| 하는 사람 | 사람이 studio 에서 칸을 그림 (OCR·모델 필요 없음) | 대형 모델이 만들고 사람이 검사 |

**A 순서** (자세히 [new-forms.md 0절](new-forms.md#0-그림-위에-그려서-만들기-overlay)):

1. 새 서식 추가 › A: 그림, 서식 ID(`img_…`), 서식 이름 → **만들고 영역 편집으로**
2. 값이 들어갈 자리마다 칸을 그림 (글자 칸 T, 표 B, 날짜 칸 D, 체크 C, 서명 S, 자유 위치 F)
3. 칸마다 **항목명**(그림에 인쇄된 이름) → **키**(대개 자동, [keys.md](keys.md)) → **생성 방법**(고르기 창, 없으면 [generators.md](generators.md))
4. **저장** → 그림·검수 › 미리보기, 질문·답 › 실제 문항 → **검수 완료**
5. 검수 완료된 서식은 레시피의 `"all"` 에 들어가 데이터셋에 나옵니다

칸만 그리면 분류·값 추출·체크·표·OCR·자유 기재 문항이 같이 생깁니다. 업무(여러 서류) 문항에 넣으려면 시나리오·묶음에서 그 업무의 서류로 넣습니다.

## 3. 데이터셋

화면 위에서부터 **새로 만들기 → 생성 현황 → 등록된 데이터셋 → 학습 기록** 순입니다.

### 만들기

1. **새로 만들기**에서 레시피 줄의 이름을 정하고 **[만들기]**.

   | 레시피 | 만드는 것 |
   |---|---|
   | `bank-bench` | 은행 서류·업무 **평가 세트** |
   | `bank-train` | 은행 서류·업무 **학습 데이터** |
   | `ocr-bench` · `ocr-train` | 쪽 OCR 평가 세트 · 학습 데이터 |

   용도(평가 세트 / 학습 데이터)는 레시피가 정합니다 (용도 열). 이름은 기본이 `<레시피>-<날짜>`, 프로세스는 동시에 그리는 수 (기본 4).
   레시피 이름을 누르면 서식·업무·수량·촬영 조건을 고칩니다. **`bank-bench` 같은 기본 레시피를 고치면 저장소 파일(`docgen/recipes/<이름>.json`)이 바뀝니다** — 시험이나 다른 설정은 **틀에서 새 레시피**로 따로 만듭니다 (`bank-try` = 몇 분짜리 시험). 칸 설명은 [data.md 4절](data.md#4-명령으로-만들기-remote_buildpy).
2. **생성 현황**에서 진행을 봅니다. 끝나면 **등록된 데이터셋**에 저절로 들어갑니다.
3. **처음에는 작게** 만들어 문항을 보고, 괜찮으면 크게 만듭니다. 평가 세트는 한 번 정하면 바꾸지 않습니다 (데이터셋 위 **[고정]**).

### 데이터셋 하나

| 탭 | 하는 일 |
|---|---|
| 설명서 | 구성·점수(자동)와 목적·한계(사람이 적음) |
| 구성·추적 | 과제·업무·정답 구조별 문항 수 |
| **문항** | 그림 + 질문 + 정답 박스. **사람이 눈으로 확인하는 곳** (형식 검사 통과 ≠ 검수) |
| 업무 묶음 | 같은 고객의 서류 묶음, 빠짐·타인·변조 (bank 만) |
| 모델 답 | 학습 결과나 답 파일을 붙여 채점 |
| **학습** | 학습 데이터·평가 세트를 골라 **설정 파일 쓰기** → studio 쪽 코드 폴더에 `train/configs/studio-<이름>.json`. 학습 서버로 옮겨 실행 ([start.md 4절](start.md#4-학습-설정-만들기)). 어느 데이터셋에서 열어도 같은 화면 |

명령으로 만들기(`remote_build.py`), 결과 폴더 구조, 레시피 칸 전체는 [data.md](data.md).
**폴더 등록**(맨 아래 접힌 칸)은 studio 밖에서 만든 데이터셋 폴더를 목록에 넣을 때만 씁니다.
