# 새 서식 추가하기

서식 그림 한 장에서 시작해 합성 데이터에 쓰이는 서식으로 올리기까지의 절차입니다. 길이 둘입니다.

| | A. 그림 위에 그려서 (overlay) | B. 대형 모델로 html 서식 |
|---|---|---|
| 모양 | 올린 그림 그대로 (칸 수·위치 고정) | 모델이 만든 html (글꼴·행 수·쪽이 바뀜) |
| 하는 사람 | 사람이 studio 에서 칸을 그림 | 모델이 만들고 사람이 검사 |
| 필요한 것 | 서식 그림만 (OCR·모델 없음) | 대형 모델, 검사 |
| 합성 OCR 세트 (쪽 전체 받아쓰기) | 못 씀 (배경 글자 정보 없음) | 씀 |

A 는 아래 0절, B 는 1절부터입니다.

---

## 0. 그림 위에 그려서 만들기 (overlay)

studio **새 서식 추가 › A. 그림 위에 그려서 만들기**:

1. 그림(PNG·JPG·PDF, 여러 쪽이면 쪽 순서대로)을 고르고 **서식 ID**(`img_` 로 시작, 예: `img_payslip_a`), **서식 이름**을 적습니다.
   서식 이름이 문서 분류(`classify`)의 정답입니다.
   값이 적힌 실서류 견본이면 **실서류 견본**을 켠 채로 둡니다 → 사내 서식 폴더(`private_forms_dir`)에만 만들어집니다 (설정에 없으면 거부). 빈 서식·공개 서식이면 끄면 저장소 `docgen/forms/<ID>/`.
2. **만들고 영역 편집으로** → 그 서식의 영역 편집이 열립니다. 쪽 크기는 A4 에 맞춰집니다 (긴 변 842pt).
3. 칸을 그립니다. 도구: 글자 칸(T)·**표(B)**·체크 보기(C)·서명·도장 자리(S)·결재란(R)·지우기(E·A).
   - **글자 칸**: 그리면 오른쪽에 **항목명** 입력이 바로 나옵니다. 그림에 인쇄된 이름 그대로 적습니다 (예: `성명`). 질문(무엇을 읽을지)과 키가 이것으로 정해집니다.
     `성명`·`생년월일`·`연락처` 처럼 키 사전에 있는 항목명은 공통 키(`customer.name` …)가 자동으로 붙습니다. 저장한 뒤 키 고르기에서 바꿀 수 있습니다.
   - **값 만들기 › 생성 방법**: 문서를 만들 때마다 이 칸에 넣을 값을 고릅니다 (`fields.json` 의 `source`, [값 출처 목록](../docgen/forms/_common/values.md)).
     | 고르는 것 | 값 |
     |---|---|
     | 자동 | 항목명으로 값 종류를 추정해 만듦. 추정 못 하는 칸(예: `적요`)은 **빈 칸**으로 나오니 꼭 고릅니다 |
     | 종류에 맞는 그럴듯한 값 (날짜·원화 금액·계좌번호·전화번호·회사명·상품명·사유 …) | 문서마다 새로 만듦 |
     | 보기 중 하나 | 아래 보기 목록(한 줄에 하나)에서 하나. 예: 적요 → 이체·입금·출금 |
     | 늘 같은 글자 · 짧은 자유 문장 · 늘 빈 칸 | |
     | 행마다 늘어나는 날짜 | 표의 날짜 열 (거래일 등) |
     | 고객 정보 (`person.name` …) | 같은 고객의 다른 서류와 같은 값 — 서류 대조 과제에 필요 |
     표 칸에서 고르면 **같은 열의 모든 행**에 같이 들어갑니다. 칸끼리 관계(합계 = 행의 합, 시작일 ≤ 종료일)는 생성 방법으로 안 되고 `generate.py` 로 맞춥니다.
   - **표**: **표 그리기**(B)로 표에서 값이 적히는 행들(머리글 줄은 빼고)을 끌어 감쌉니다. 오른쪽에 **열 항목명**(한 줄에 하나, 그림의 머리글 그대로), **행 수**, **표 묶음** 이름(예: `거래`)을 적고 **표 칸 만들기** → 열 × 행 칸이 한 번에 생깁니다 (열은 같은 폭).
     열 폭이 그림과 다르면 첫 행의 그 열 칸을 고르고 크기를 고친 뒤 **이 열 폭을 모든 행에**. 행이 모자라면 마지막 행에서 **이 행 복제**(아래로 몇 행, 행 간격 pt).
     글자 칸을 하나씩 그려 **표의 반복 행 칸**을 켜도 됩니다. 같은 항목명이 두 행 이상이어야 표가 됩니다. 문서마다 채우는 행 수는 생성기가 정합니다.
   - **체크**: 보기마다 □ 를 그리고 보기 글자를 적습니다 (같은 영역을 고른 채로 다시 그리면 보기가 늘어남).
   - 실서류 견본이면 남은 값을 **지우기**로 덮습니다. 안 지우면 그 값이 생성 그림마다 복제됩니다 (개인정보).
4. **저장** → **그림·검수 › 미리보기**에서 값이 칸에 들어가는지, **질문·답 › 실제 문항**에서 질문·정답을 봅니다 → 사람이 보고 **검수 완료** (7절).
   그린 서식(`img_*`)은 **검수 완료 전에는** 레시피의 `"all"`·그룹 선택에 들어가지 않습니다 (레시피에 ID 를 직접 적으면 시험용으로 들어감).

칸만 그리면 생기는 과제: `classify`(서식 이름), `kie`(글자 칸), `marks`(체크·서명·도장), `ocr_page`·`ocr_field`(값), `table`·`table_find`·`table_qa`(표 행),
`freetext`(항목명이 비고·기타·사유·용도인 칸). 사람이 더 해야 하는 것: 이 서식만의 질문은 `qa.py`(6절 표), 여러 서류 업무 과제는 ③ 시나리오에 넣기(7절).
`table_read`(표 머리글까지 그대로)는 html 서식만 됩니다.

---

```text
서식 그림 ──▶ ① 대형 모델: 초안 폴더 (template.html.j2 + form.json)
                 │   그려 보며 원본과 맞춤 (python -m docgen.preview --dir)
                 ▼
             ② 사람: 검사 통과 확인 (생성 스크립트가 있으면 읽기) → studio 서식 폴더로 옮기기 → studio [서식 다시 읽기]
                 ▼
             ③ 사람: studio ① 서식에서 손보기 (값 출처, 빠진 칸, 위치) → 검수 완료
                 ▼
             ④ 시나리오·레시피에 넣어 데이터셋 생성
```

## 1. 모델이 만들 결과물 (B. html 서식)

모델에게는 **폴더 하나에 파일 둘**(`template.html.j2` 모양 + 값 자리, `form.json` 이름·그룹 + 칸 목록)을 만들게 합니다.
칸끼리 관계(합계·순서·조건)가 있으면 `generate.py`, 이 서식만의 질문이 있으면 `qa.py` 를 더합니다 (둘 다 선택).

형식 전부(템플릿 문법, 칸 목록, 키 이름, 흔한 실수, 검사 통과한 전체 예시)는 [docgen/manual/NEW_FORM_SPEC.md](../docgen/manual/NEW_FORM_SPEC.md) 하나에 있습니다.
**모델에게는 이 파일을 통째로 줍니다.** 사람이 꼭 알아 둘 것은 둘입니다.

- **값 자리는 모두 `f("키", label="원본 항목명")`** (체크 `m.choice`, 도장 `m.seal`, 서명 `m.sigspot`). `{{ d.x }}` 로 찍으면 그림엔 나와도 정답에서 빠집니다.
- **키 이름이 가장 중요합니다.** 학습 정답의 키가 됩니다. 있는 키(`docgen/forms/_common/dictionary/common.json`, `keys.json`)를 먼저 쓰고, 없으면 "누구의 무엇" 영어 키 ([키 이름 규칙](../docgen/forms/_common/README.md#키-이름-규칙)).

## 2. 시작 전에

| 확인 | 내용 |
|---|---|
| **어떤 그림을 모델에 보내나** | 외부 대형 모델(클로드 등)에는 **빈 서식·공개 서식 그림만**. 값이 적힌 실서류 견본은 외부로 보내지 않습니다 (AGENTS.md 규칙 10). 실서류 견본뿐이면 사내 모델에 맡기거나, 빈 서식 그림을 구합니다 |
| 서식 ID | 영어 소문자로 시작, 소문자·숫자·밑줄 3~51자. 겹치는지 `python -m docgen.formdir path <ID>` (파일 목록이 나오면 이미 있는 ID. 새 ID 면 "서식 ID '<ID>' 가 없습니다 (새 서식이면 쓸 수 있는 ID)" 와 비슷한 ID 가 나옴) |
| 같은 서식이 이미 있나 | studio ① 서식에서 이름 검색. 비슷한 html 서식이 있으면 새로 만들기보다 **복제** 후 고치는 편이 빠름 |
| 넣을 곳 | 공개·빈 서식에서 만든 것: `docgen/forms/<ID>/` · 실서류에서 만든 것: 사내 서식 폴더 `$DOCGEN_PRIVATE_FORMS/<ID>/` |

## 3. 모델에게 맡기기

### 넘길 것

- 서식 그림 (여러 쪽이면 쪽마다)
- [docgen/manual/NEW_FORM_SPEC.md](../docgen/manual/NEW_FORM_SPEC.md)
- 키 사전: `docgen/forms/_common/dictionary/common.json`, `docgen/forms/_common/keys.json` (저장소를 열 수 있는 모델이면 경로만)

### 지시문 (그대로 붙여 넣기, `<…>` 만 바꿈)

```text
첨부한 서식 그림과 똑같이 생긴 docgen html 서식을 만들어라. 형식은 NEW_FORM_SPEC.md 를 따른다.

결과: work/<이름>/template.html.j2 와 work/<이름>/form.json (form.json 에 fields·lists 포함, 9절 예시 꼴).
- 그림에 인쇄된 글자(제목·항목명·안내문·보기·주석)는 빠짐없이 옮긴다. 그림에 적힌 개인 값(이름·번호·주소·금액)은 옮기지 말고 값 자리로 바꾼다.
- 사람이 쓰거나 출력되어 채워지는 자리는 모두 값 자리로 만든다: 글자 f(), 체크 m.choice, 도장 m.seal, 서명 m.sigspot.
  label 은 그림에 인쇄된 항목명 그대로.
- 행 수가 바뀌는 표는 {% for r in d.<목록> %} 반복 행과 form.json lists(min = 그림에 보이는 행 수)로.
- 키는 docgen/forms/_common/dictionary/common.json, docgen/forms/_common/keys.json 에 있는 것을 먼저 쓰고, 없으면 "누구의 무엇" 영어 키를 새로 짓는다.
- 값 출처(source)는 맞는 profile.* 이나 rule:* 를 고르고, 모르겠으면 rule:note.
- 칸끼리 관계(시작일 ≤ 종료일, 합계 = 행의 합, 잔액, 조건부 칸, 금액 한글 표기)가 있으면 work/<이름>/generate.py 의
  adjust(d, p, rng) 로 맞춘다 (NEW_FORM_SPEC.md 8절: docgen.formkit 과 표준 라이브러리만, 난수는 rng 만, 새 키 금지).
- 서식 이름: <서식 이름>, 그룹: <finance 등>, 종류: <external|internal>

끝내기 전에 아래 두 명령으로 그려서 원본 그림과 비교하고, 비슷해질 때까지 고친다.
  python -m docgen.preview --dir work/<이름> --rows min --out work/<이름>_min
  python -m docgen.preview --dir work/<이름> --rows max --out work/<이름>_max
마지막 줄 JSON 에서 overflow 가 false, checks 가 [] 이고, --rows min 의 pages 가 원본 쪽 수와 같아야 한다.
판단이 안 선 칸(값 자리인지, 누구의 값인지)은 목록으로 따로 적어 보고한다.
```

- **명령을 직접 돌릴 수 있는 모델**(클로드 코드처럼 저장소에서 일하는 에이전트)이면 그려 보고 고치기를 스스로 반복합니다.
- **채팅만 되는 모델**이면 사람이 위 명령을 대신 돌리고, 그려진 그림(`images` 경로)과 마지막 줄 JSON 을 붙여 "원본과 다른 곳을 고쳐"로 몇 번 주고받습니다.

## 4. 검사

모델이 끝났다고 해도 사람이 한 번 더 돌립니다.

```bash
python -m docgen.preview --dir work/<이름> --rows min --out work/check_min
python -m docgen.preview --dir work/<이름> --rows max --out work/check_max
```

| 볼 것 | 통과 |
|---|---|
| 명령이 오류 없이 끝남 | 템플릿 문법이 맞음 |
| `overflow` | `false` |
| `checks` | `[]` — 키가 칸 목록과 템플릿에서 안 맞으면 여기 나옴 |
| `pages` (`--rows min`) | 원본 쪽 수와 같음 (`--rows max` 는 늘어도 됨, 자동 쪽 나눔) |
| 그림 (`images` 경로) | 원본과 나란히 놓고: 표 구조·문구가 같은지, 값이 칸 안에 들어가는지 |
| 템플릿에 `{{ d.` | 없어야 함 (값을 직접 찍으면 정답 라벨에서 빠지는데 검사가 못 잡음) |
| `generate.py` (있으면) | **사람이 읽음**: `docgen.formkit`·표준 라이브러리만 쓰는지, 파일·네트워크·`os`·`subprocess` 가 없는지, 하는 일이 원본의 칸 관계와 맞는지. seed 몇 개로 그려 관계가 지켜지는지 |

## 5. studio 에 넣기

초안 폴더를 서식 폴더 꼴(`look/template.html.j2` + `form.json` + `fields.json`)로 옮깁니다. 저장소 루트에서:

```bash
# 공개·빈 서식에서 만든 것 → docgen/forms/<ID>/
python - work/<이름> <서식ID> <<'EOF'
import json, shutil, sys
from pathlib import Path
from docgen import formdir, htmlform as H
src, form_id, root = Path(sys.argv[1]), sys.argv[2], (sys.argv[3] if len(sys.argv) > 3 else None)
assert H.ID_RX.fullmatch(form_id), "서식 ID 형식 (영어 소문자로 시작, 소문자·숫자·밑줄 3~51자)"
dest = formdir.new_dir(form_id, Path(root) if root else None)   # 이미 있으면 멈춤 (덮어쓰지 않음)
shutil.copyfile(src / "template.html.j2", dest / "look" / formdir.TEMPLATE)
H.write_form(dest, json.loads((src / "form.json").read_text(encoding="utf-8")))   # form.json + fields.json 으로 나눔
for extra in ("source.png", "generate.py", "qa.py"):   # 원본 그림, 생성 스크립트·서식 전용 질문 (읽고 확인한 것만, 있으면)
    if (src / extra).exists():
        shutil.copyfile(src / extra, dest / extra)
print(dest)
EOF
```

실서류에서 만든 서식은 명령 끝에 사내 서식 폴더를 더 적습니다: `python - work/<이름> <서식ID> "$DOCGEN_PRIVATE_FORMS" <<'EOF'` (나머지 같음).

그다음 **studio ① 서식 › [서식 다시 읽기]** 를 누릅니다. "새로 1" 과 함께 목록에 나오면 끝입니다 (studio 를 다시 띄우지 않아도 됨).
폴더가 깨져 있으면 등록하지 않고 이유(JSON·템플릿 문법 몇 번째 줄·ID 형식·ID 겹침)를 보여 줍니다.

확인:

```bash
python -m docgen.formdir path <서식ID>                    # 파일 자리
python -m docgen.formdir check <서식ID>                   # 서식 검사: 칸 목록·값 출처·질문 설정·카드 (형식 검사일 뿐 검수 아님)
python -m docgen.preview <서식ID> --rows max --out work/<서식ID>
python -m docgen.formdir card <서식ID>                     # 서식 카드 FORM.md (항목·위치·질문→답 예시) — 서식 폴더 설명서 docgen/forms/README.md
```

## 6. studio 에서 손보기

① 서식 › 그 서식을 엽니다. 고칠 것에 따라 화면이 다릅니다.

| 고칠 것 | 어디서 |
|---|---|
| 빠진 자리, 조건 칸 확인 | **자리·템플릿**: 값이 나올 수 있는 모든 자리가 공란 그림 위에 나오고, 그려 본 문서에 안 나온 키는 따로 목록 |
| 값 출처 (값이 그럴듯하지 않음, 서로 안 맞음) | **자리·템플릿**: 자리를 눌러 오른쪽에서 값 출처·고정 값 (`fields.json`) |
| 칸 더하기 | **자리·템플릿**: 그림의 빈칸을 누르고 **[자리 넣기]** (종류·키·항목명·값 출처) → 미리보기 → 저장 |
| 칸 빼기, 위치, 표 구조, 인쇄 문구, 선 | **자리·템플릿**의 템플릿 (자리를 누르면 그 줄로 감) → 미리보기 → 저장. 빠지거나 생기는 키를 저장 전에 알려 줌. 또는 모델에게 다시 맡기기 |
| 레이아웃 변형마다 | **자리·템플릿** 위의 레이아웃 고르기. 한 레이아웃에만 있는 키는 "…에 없음" 으로 표시 |
| 키 이름 | 템플릿의 `f("키")` 와 `fields.json` 을 같이 |
| 반복 행 수·서식 이름·그룹 (`form.json`), 원본 그림 겹쳐 보기, 분석기에 다시 맡기기 | **html 편집** |
| 칸끼리 관계 (순서·합계·조건·표기) | 서식 폴더의 `generate.py` (파일로. 내용은 **파일** 탭에서 보임) |
| 질문 문장·답 모양 (칸마다 묻기·항목명은 `fields.json` 그 칸의 `q`) | 서식 폴더의 `questions.json` — 기본과 다르게 할 것만 ([서식 폴더 설명서 5절](../docgen/forms/README.md#5-질문과-답-고치기)) |
| 이 서식만의 질문 | 서식 폴더의 `qa.py` — 함수 하나 = 질문 하나 (견본 `python -m docgen.formdir qa <ID> --new`) |

- html 서식의 자리는 문서마다 다시 계산되므로 (글꼴·행 수·쪽이 바뀜) 그림 위에 고정 위치로 그리지 않고 템플릿에서 고칩니다.
- 이미 등록된 서식의 템플릿·`fields.json` 을 파일로 고친 것은 [서식 다시 읽기] 없이 다음 미리보기에 바로 나옵니다.
- 모양을 다시 크게 고쳐야 하면 [docgen/manual/FORM_SHELL_GUIDE.md](../docgen/manual/FORM_SHELL_GUIDE.md) 와 함께 모델에게 맡깁니다 (키는 그대로 두고 모양만).

## 7. 검수하고 데이터셋에 넣기

1. **검수**: ① 서식 › 검수 탭. 미리보기를 원본과 나란히 보고(행 최소·최대, seed 몇 개) **검수 완료**. 학습/평가 배정도 여기서.
   형식 검사 통과는 검수 완료가 아닙니다 (AGENTS.md 규칙 7). 검수 뒤 서식 파일이 바뀌면 "재검수 필요"로 돌아갑니다.
2. **업무에 넣기**: ③ 시나리오·묶음에서 그 서식이 제출되는 업무에 더합니다.
3. **데이터셋**: ⑥ 데이터셋 › 새로 만들기(레시피)에서 서식·시나리오를 고릅니다 ([data.md](data.md)).
   **html 서식은 검수 전이어도 레시피의 `"all"`·그룹 선택에 들어갑니다.** 검수한 서식만 쓰려면 레시피의 **검수 완료 서식만**(`reviewed_only`)을 켜거나, 검수가 끝날 때까지 `exclude` 에 그 ID 를 적어 둡니다.

## 8. 문제 해결

| 증상 | 할 일 |
|---|---|
| checks: `form.json 에 선언했는데 템플릿에 안 나오는 키` | 칸 목록에만 있는 키 → 템플릿에 넣거나 칸 목록에서 빼기 |
| checks: `템플릿에 있는데 값이 없는 키` | 템플릿 키가 칸 목록에 없음 (오타 포함) |
| 한 쪽 서식이 2쪽으로 | 높이·간격·글자 크기를 줄이게 모델에 다시 |
| 아래쪽이 점점 밀림 | 행 높이를 px 로 직접 (padding 아님) |
| `키 'a' 와 'a.b' 를 함께 쓸 수 없습니다` | 한 키가 다른 키의 앞부분 (NEW_FORM_SPEC 4절 키 이름) |
| [서식 다시 읽기] 의 문제: `코드 서식과 ID 가 겹칩니다` | 다른 ID 로 폴더 이름을 바꾸고 다시 누르기 |
| 5절 명령이 `FileExistsError` | 같은 ID 폴더가 이미 있음. 다른 ID 를 쓰거나, 기존 서식을 고칠 거면 6절로 |
| `생성 스크립트 generate.py N번째 줄: …` | 그 줄의 오류. 이 서식만 그려지지 않음 |
| checks: `같은 seed 로 두 번 돌렸는데 결과가 다릅니다` | 스크립트가 `rng` 말고 `random`·시간 등을 씀 → `rng` 로 |
| checks: `칸 목록에 없는 키를 만들었습니다` | 스크립트가 새 키를 만듦 → 칸 목록 `fields` 에 선언하고 템플릿에 `f()` 로, 아니면 지우기 |
| 목록의 "키" 수가 0 | 목록의 그 칸은 미리 만든 카탈로그에서 읽어 새 서식은 0. 상세·미리보기에는 정상으로 나옴 |
