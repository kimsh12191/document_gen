# 새 서식 추가하기

서식 그림 한 장에서 시작해 합성 데이터에 쓰이는 서식으로 올리기까지의 절차입니다. 새 서식은 **그림 위에 칸을 그려서(overlay)** 만듭니다.
말 뜻은 [용어 한 장](terms.md). 이미 있는 html 서식을 코드로 고치는 것은 [서식 고치기](../docgen/forms/README.md).

## 외주 체크리스트 (처음 맡았을 때)

| 단계 | 할 일 | 자세히 |
|---|---|---|
| 1. 받기 | 코드 묶음(이 저장소)과 서식 그림. **값이 적힌 실서류 견본이면 사내 PC·서버에서만** 작업하고 외부 모델·서비스에 보내지 않음 | |
| 2. studio 띄우기 | 서버(도커): `sh docker/studio.sh --data <저장 폴더>` · 내 PC: `pip install -r docgen/requirements.txt -r studio/requirements.txt` → `python -m studio` → `http://localhost:8765` | [docker/README.md](../docker/README.md), [studio/README.md](../studio/README.md) |
| 3. 만들기 | 칸을 그리고 칸마다 키 · 키 설명 · 생성 방법 | 1절 · [keys.md](keys.md) · [generators.md](generators.md) |
| 4. 스스로 확인 | `python -m docgen.formdir check <ID>` 에 문제 없음 · studio 서식 › 그림·검수 › **검수**의 자동 검사 경고 없음 (한글 키, 같은 키를 여러 칸, 지우지 않은 실서류 값) · 미리보기를 seed 3개 이상 넘겨 봄 | 2절, [keys.md](keys.md) |
| 5. 넘기기 | 서식 폴더 `docgen/forms/<ID>/` 전체 (실서류면 사내 서식 폴더) · 더한 생성 함수(`docgen/forms/_common/generators.py`, 썼으면) · 미리보기 그림 몇 장 · 판단이 안 선 칸 목록 | [generators.md 4절](generators.md#4-넘길-때) |
| 6. 합격 | 사내 담당자가 그림·정답을 보고 **검수 완료**를 누름 (외주가 누르지 않음). 검수 완료된 서식만 데이터셋 `"all"` 에 들어감 | 2절 |

## 1. 그림 위에 그려서 만들기

### 순서

1. studio **새 서식 추가**: 그림(PNG·JPG·PDF, 여러 쪽이면 쪽 순서대로), **서식 ID**(`img_` 로 시작, 예: `img_payslip_a`), **서식 이름**(= 문서 분류 정답).
   값이 적힌 실서류 견본이면 **실서류 견본**을 켠 채로 → 사내 서식 폴더에만 만들어집니다 (아래 "저장 위치").
2. **만들고 영역 편집으로** → 그 서식의 영역 편집이 열립니다 (쪽 크기는 A4, 긴 변 842pt).
3. 값이 들어갈 자리마다 칸을 그리고, 칸마다 **키 · 키 설명 · 값**을 정합니다 (아래 두 표).
4. **저장** → **그림·검수 › 미리보기**(값이 칸에 맞는지), **질문·답 › 실제 문항**(질문·정답) → 사람이 보고 **검수 완료** (2절).
   검수 완료 전에는 레시피의 `"all"`·그룹 선택에 들어가지 않습니다 (레시피에 ID 를 직접 적으면 시험용으로 들어감).

### 도구

| 도구 | 쓰는 곳 | 하는 것 |
|---|---|---|
| 글자 칸 (T) | 이름·금액·번호 등 값 하나 | 끌어서 그리면 오른쪽에 키·키 설명 입력 |
| **표** (B) | 행이 반복되는 표 | 값이 적히는 행들(머리글 줄 빼고)을 감싸고 열 설명·행 수 → **표 칸 만들기** (아래 "표") |
| **날짜 칸** (D) | `____년 __월 __일` 처럼 나뉜 날짜 | 칸을 고른 채로 년 → 월 → 일 숫자 자리를 차례로 끔 |
| 체크 보기 (C) | □ 보기 | 보기마다 □ 를 그리고 보기 글자를 적음 (같은 영역을 고른 채로 다시 그리면 보기가 늘어남) |
| 서명·도장 자리 (S), 결재란 (R) | 서명란, 은행 직원 결재 칸 | |
| **자유 위치** (F) | 접수인·일부인·원본대조필, Ref No 처럼 서류마다 아무 데나 찍히는 것 | 나올 수 있는 영역을 감싸고 종류·나올 확률 (아래 "자유 위치") |
| 지우기 (E·A) | 실서류 견본에 남은 값 | 덮어 지움. **안 지우면 그 값이 생성 그림마다 복제됩니다** (개인정보, 검수 탭이 경고) |

### 칸마다 정하는 것

| 정하는 것 | 어떻게 | 자세히 |
|---|---|---|
| **키** | 질문·정답에 나가는 이름. 이 서식 안에서만 정합니다 (다른 서식과 맞출 필요 없음). 영어 소문자·숫자·`_`·`.` (`customer.name`) | [키 이름 정하기](keys.md) |
| **키 설명** | 무엇을 읽는 칸인지. 보통 그림에 인쇄된 이름 그대로 (`성명`). 질문에 `- 키: 키 설명` 으로 나갑니다 | |
| **값** | **생성 방법 [고르기…]** — 문서마다 이 칸에 넣을 값. 카드에 실제로 나오는 값의 예가 보임. 표 칸은 같은 열 전체에 같이 | 아래 |
| 표기 (선택) | 날짜·금액을 서식에 인쇄된 꼴로: `250131`, `1,234,000원`, `일금 일백이십삼만사천원정`. 안 정하면 문서마다 꼴이 섞임 | |

생성 방법 고르기 창:

| 고르는 것 | 값 |
|---|---|
| 자동 (고르지 않음) | 키가 고객 정보 키(`customer.name` 같은)면 그 고객의 값, 아니면 칸의 값 종류(`kind`)대로, 둘 다 아니면 **빈 칸**. 값이 필요한 칸은 꼭 고릅니다 (칸 목록 **생성** 열에 빨간 "자동 → 빈 칸") |
| 고객 정보 (이름·생년월일·주소·직장 …) | 그 서류의 고객 값 (한 서류 안에서 같은 칸은 같은 값) |
| 날짜·금액·숫자 / 기관·금융 / 글자 | 종류에 맞는 그럴듯한 값, 문서마다 새로. 표의 날짜 열은 **행마다 늘어나는 날짜** |
| 직접 정하기 | **보기 중 하나**(이체·입금·출금), **틀로 만들기**(`HN-####-{A\|B}` → `HN-4821-B`), 늘 같은 글자, 늘 빈 칸. 보기·틀은 그 칸에만 저장됨 |
| 공통 값 종류 · 직접 만든 생성기 | 여러 서식이 같이 쓰는 값 종류(`docgen/forms/_common/key_rules.json` 의 `kinds`) · `docgen/forms/_common/generators.py` 에 더한 함수 |

**원하는 것이 없으면** → **[원하는 값이 고르기 창에 없을 때](generators.md)** (고르기 창 맨 아래에도 같은 안내). 세 길입니다.

1. 고르기 창에서 보기·틀을 적는다 (코드 없음)
2. 값 하나를 만드는 함수를 `docgen/forms/_common/generators.py` 에 하나 더한다
3. 여러 칸이 서로 맞아야 하면(합계 = 행의 합, 시작일 ≤ 종료일) 서식 폴더 `generate.py` 로 **칸끼리 관계**를 맞춘다 (영역 편집 위 **[견본 만들기]**)

### 표

**표 그리기**(B)로 값 행들을 감싸고 오른쪽에서 정한 뒤 **표 칸 만들기** → 열 × 행 칸이 한 번에 생깁니다.

| 칸 | 뜻 |
|---|---|
| 열 설명 | 한 줄에 하나, 그림의 머리글 그대로 |
| 행 수 · 표 묶음 | 그림에 인쇄된 줄 수, 서식 안의 표마다 다른 이름 |
| 표 제목 | 그림의 표 제목. 질문이 이 이름으로 표를 가리킴 |
| 채우는 행 수 | 1~3행(기본) · 절반쯤 · 모든 행 · 1행~모든 행 고르게. 넘치는 행은 가끔 별지로 |
| 영문 키 (선택) | 표 키(`deals`)·열 키(`date`) → 키 `deals.<행>.date`. 비우면 한글 키 ([keys.md 4절](keys.md)) |

열 폭이 그림과 다르면 첫 행의 그 열 칸 크기를 고친 뒤 **이 열 폭을 모든 행에**, 행이 모자라면 마지막 행에서 **이 행 복제**. 표 칸을 고르면 제목·채우는 행 수를 다시 바꿀 수 있습니다.

### 날짜 칸

년 → 월 → 일 자리를 차례로 끕니다. 생성 방법을 안 고르면 서류 날짜(신청·작성·발급일), 생년월일 같은 다른 날짜면 그 생성 방법을 고릅니다. 연도 2자리도 고를 수 있습니다.

### 자유 위치 (도장·번호)

나올 수 있는 영역과 종류·**나올 확률**을 정하면, 문서마다 그 안에서 자리·기울기가 바뀌고 값 칸과 많이 겹치지 않게 찍힙니다 (인쇄 글자 위에는 겹쳐 찍힘).
도장 글자에 `{date}`(서류 날짜) `{bank}` `{branch}` `{name}` 를 쓸 수 있고, **도장 글자를 정답에** 를 켜면 내용 추출 정답에도 들어갑니다 (끄면 찍혔는지·위치만). 번호는 늘 정답에 들어갑니다.
**모든 서식에 공통**으로 넣으려면 studio **표시 요소 › 자유 위치 도장·번호** (원본·그린·html 서식 전체).

### 배경 글자 (합성 OCR 세트)

영역 편집 위 **배경 글자: [사내 OCR 로 읽기]** → 그림 속 인쇄 글자가 쪽 전체 받아쓰기 정답에 들어갑니다. 읽기 전에는 합성 OCR 세트에서 빠집니다.
studio 설정의 사내 OCR(`ocr.callable`·`revision`)이 있어야 합니다. 실서류 그림을 외부 OCR 로 보내지 않습니다.

### 저장 위치

**실서류 견본**을 켜면 사내 서식 폴더(`private_forms_dir`)에만 만들어집니다: 도커 studio(`docker/studio.sh --data <저장 폴더>`)는 `<저장 폴더>/private_forms`, 도커 없이는 코드 폴더의 `studio_private_forms/`(git 에 올라가지 않음).
바꾸려면 `studio/config.json` 에 `{"private_forms_dir": "<경로>"}`. 끄면 저장소 `docgen/forms/<ID>/`.

### 생기는 과제

칸만 그리면: `classify`(서식 이름), `kie`(글자 칸), `marks`(체크·서명·도장), `ocr_page`·`ocr_field`(값), `table`·`table_find`·`table_qa`(표 행),
`freetext`(키 설명이 비고·기타·사유·용도인 칸). 이 서식만의 질문은 서식 폴더 `qa.py` ([서식 고치기](../docgen/forms/README.md)).

## 2. 검수하고 데이터셋에 넣기

1. **검수**: 서식 › 그림·검수 › 검수. 미리보기를 원본과 나란히 보고(seed 몇 개) **검수 완료**. 학습/평가 배정도 여기서.
   형식 검사 통과는 검수 완료가 아닙니다 (AGENTS.md 규칙 7). 검수 뒤 서식 파일이 바뀌면 "재검수 필요"로 돌아갑니다.
2. **데이터셋**: 데이터셋 › 새로 만들기(레시피)에서 서식을 고릅니다 ([data.md](data.md)).

## 3. 문제 해결

| 증상 | 할 일 |
|---|---|
| 칸 목록 **생성** 열에 빨간 "자동 → 빈 칸" | 생성 방법을 고르지 않았고 키가 고객 정보 키가 아님 → 생성 방법 [고르기…] |
| 검수 탭 경고: 한글 키 · 같은 키를 여러 칸 | 키를 영어로, 칸마다 다르게 ([keys.md](keys.md)) |
| 검수 탭 경고: 지우지 않은 실서류 값 | 영역 편집의 **지우기**로 덮기 |
| `생성 스크립트 generate.py N번째 줄: …` | 칸끼리 관계 스크립트의 그 줄 오류. 이 서식만 그려지지 않음 ([generators.md](generators.md)) |
| checks: `같은 seed 로 두 번 돌렸는데 결과가 다릅니다` | 스크립트가 `rng` 말고 `random`·시간 등을 씀 → `rng` 로 |
| 배경 글자가 합성 OCR 세트에 안 나옴 | 영역 편집 위 **[사내 OCR 로 읽기]** (studio 설정의 사내 OCR 필요) |
